# 3D 시제품: 범위와 물리 접근 두 가지 (개발 쪽 정리, 2026-11-19)

GPT의 v0.11.0 검토(5·6장)를 받아 개발 쪽에서 짧게 정리한 것이다. 본편 구현 계획이 아니며, 엔진과 물리 구조는 아직 정하지 않았다. 사용자가 범위를 확정한 뒤 별도 작업(별도 브랜치나 프로젝트)으로 시작한다.

## 바로잡는 것
- 앞서 "리플레이·유령·시범 때문에 3D에서도 직접 짠 고정 간격 계산을 옮겨 쓰는 편이 안전하다"고 적었는데, 지나친 말이었다. **리플레이는 완전 결정론을 필수로 하지 않는다.**
  - 리플레이(v0.11.0부터): 몸의 모습을 적어 둔 것을 다시 보인다. 물리가 무엇이든 된다.
  - 시범: 미리 녹화한 모습을 틀어 줘도 된다. 입력을 다시 넣어 계산하는 지금 방식은 여러 방법 가운데 하나다.
  - 유령: 시범의 모습 기록을 함께 틀면 된다.
- 고정 시간 간격은 여전히 유리하지만(같은 기기·같은 빌드에서 결과가 고르게 나옴), 그것만으로 기기·플랫폼이 달라도 같은 결과가 보장되지는 않는다.
- 입력을 다시 넣어 같은 결과를 얻어야 하는 기능(예: 입력 기록만 저장해 두었다가 다시 계산해 보기)을 3D에서도 할지는 따로 정한다. 하지 않으면 모습 기록을 저장한다.

## 작은 시제품의 범위
- 한 구역만: 평면 벽, 모서리, 돌출 턱, 짧은 틈, 발 디딜 면이 이어진 곳.
- 캐릭터 하나, 조명과 재질은 고정된 몇 가지.
- 넣지 않는 것: 도시, 끝없이 이어지는 맵, 상점, 옷, 온라인, 저장 확장, 스테이지 선택.
- 미리 정해 둔 홀드 단추를 누르는 구조로 만들지 않는다. 지형의 실제 면과 턱을 판정해 손발을 붙이고, 경로를 스스로 찾을 수 있어야 한다.

## 시제품에서 확인할 것
1. 조준: 커서가 가리키는 벽면의 점을 3D에서 고르는 방식이 손에 맞는가(선으로 첫 충돌만 찾으면 손과 몸이 벽을 뚫을 수 있다 → 부피로 경로를 확인).
2. 카메라: 둘러보는 동안 조준과 손발 명령을 잠그는가, 놓았을 때 조준을 그대로 둘지 새 중심으로 옮길지. 붙은 손발이 카메라 조작만으로 떨어지지 않아야 한다. 둘러보기 키도 다시 지정할 수 있게 할지.
3. 잡기 표시: 커서 근처의 접촉점·손을 보낼 방향·닿는 범위. "거리 안"과 "버틸 수 있음"은 다른 정보다.
4. 동작: 잡기·놓기, 발의 압력 지지와 미끄러짐, 몸 회전, 한 손 반동, 도약, 모서리 통과.
5. 같은 구간을 적어도 두 경로로 넘는 **사람의 플레이**. 자동 시범이 성공한다고 손맛이 확인된 것은 아니다.

## 물리 접근 두 가지
| | A. 엔진의 충돌 조회 + 직접 만든 등반 제어 | B. 엔진의 물리 제약(강체·관절)을 그대로 활용 |
|---|---|---|
| 방식 | 엔진에는 "여기에 무엇이 있나"만 묻고(선·부피 조회), 몸의 움직임과 손발 붙임은 직접 계산 | 몸통·팔다리를 엔진의 강체와 관절로 만들고, 근육에 해당하는 힘·모터를 건다 |
| 좋은 점 | 조작감을 직접 다듬기 쉽다. 지금 2D 판의 "의도 → 자세 → 힘" 구조를 가져가기 쉽다. 결과가 고르게 나오게 만들기 쉽다 | 충돌·쌓임·관통 방지를 엔진이 맡는다. 몸이 지형에 닿고 밀리는 일이 자연스럽게 나온다. 직접 짜는 양이 적다 |
| 걱정 | 몸과 지형의 충돌·관통 방지를 직접 만들어야 한다(3D에서는 일이 크다). 엔진의 다른 물체와 어울리게 하려면 따로 손이 간다 | 조작감을 맞추기 어렵다(관절 모터가 출렁이거나 버티지 못할 수 있다). 결과가 기기에 따라 조금씩 달라질 수 있다. 잡기·미끄러짐 같은 등반 규칙을 제약으로 표현하기 까다롭다 |
| 먼저 볼 것 | 몸통이 벽에 닿고 도는 것을 직접 만든 계산이 감당하는가 | 한 손 매달림·반동·도약에서 관절이 안정되고 조작이 뜻대로 되는가 |

- 지금 2D의 질점 6개를 그대로 3D로 늘리면 자연스러움과 충돌 문제가 풀린다고 가정하지 않는다.
- 처음에는 **몸통의 충돌·제약**과 **손발을 뻗는 계산(IK)**을 나눠서 본다. 둘을 한꺼번에 만들면 무엇이 문제인지 가리기 어렵다.
- 두 접근을 같은 작은 장면에서 견준 뒤 정한다. 섞는 안(몸통은 B, 손발과 잡기는 A)도 후보다.
- 엔진은 이 비교와 함께 정한다. 개발 쪽 사정: 장면과 코드를 글 파일로 다루기 쉬운 쪽이 지금의 작업 방식(코드 중심, 편집기 화면을 직접 보지 못함)에 맞는다.

## 2D 판의 역할
- 지금 HTML 판은 "조작·연습 기준 시제품"으로 보존한다. 조작 규칙, 연습·리플레이·차트, 키 설정의 기준이다.
- 2D에 새 메뉴·맵·과제를 크게 늘리지 않는다.
