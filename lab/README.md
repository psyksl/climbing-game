## v0.16.2: GPT의 v0.16.1 검토 N1~N3 — 리플레이의 무릎·골반, 발마다 미리보기, 로그 시각

GPT가 "모양을 다듬기 전에 먼저" 고치라고 한 세 가지입니다. 대조 시험은 `node test/review_v0161.js [결과 JSON]`(고치기 전 빌드는 `LAB=옛/lab`). 입력은 모두 스크립트이고 사람 손이 아닙니다.

- **N1 리플레이의 표시 자세**: 무릎이 굽는 방향(옆 몫)과 골반 돌림은 그림 쪽에서 부드럽게 따라가는 "표시 자세"(`SHAPE`)입니다. 고치기 전에는 그리는 함수가 이 값을 바꿨기 때문에, 리플레이에서 앞뒤로 옮기면 지금 값이 그대로 남아 무릎이 그 시각의 모양이 아니었습니다(차이 최대 14.4px, 골반 1.5).
  - 이제 표시 자세는 물리 걸음마다(`update`) 바뀌고 그리기는 읽기만 합니다. 자취의 한 장면마다 표시 자세를 함께 적고, 리플레이는 그 값을 그대로 씁니다. 리플레이를 닫으면 끝난 순간의 값으로, 새 시도는 그 자세의 값에서 바로 출발합니다(지난 시도의 값을 끌고 오지 않음).
  - 결과: 같은 시각의 무릎 자리 차이 14.35 → 0.00px(견준 시각 15곳), CPU 4배 느리게 14.19 → 0.00px(9곳). 새 시도 0.04초 뒤의 무릎 방향 차이 0.229 → 0.006, 골반 0.345 → 0.082(지난 시도 끝 값은 0.998. 남은 0.08은 출발 직후 몸이 자리 잡는 동안 부드럽게 따라가는 몫).
- **N2 발 미리보기**: 고치기 전에는 두 발 중 하나만 닿아도 보라색이었고, 오른발을 보내는 중에도 왼발 판정으로 보라색이 됐습니다.
  - 발을 고르기 전(발 조종 키를 누른 채): 조준한 자리에 어느 발이 닿는지 L·R 표시로 발마다 보입니다(닿지 않는 발은 흰 바탕).
  - 발을 보낸 뒤: 그 발과 그 발의 고정 목표만, 그 발의 판정으로 보입니다(점선이 발에서 목표로). 발 조종 키를 떼도 남습니다. 닿지 않으면 회색 점선과 "지금 자세에서는 닿지 않음".
  - 판정은 조작과 같은 함수 `CTRL.footReach`(다리 길이 + 고관절 범위)를 씁니다.
  - **판정이 실제 결과와 맞는지 쟀습니다**(`node test/foot_preview_study.js`, 시작 자세 4곳 × 조준점 107곳 × 양발 = 214번, 사람 결과 아님):

    | | 고치기 전 | 고친 뒤 |
    |---|---|---|
    | "닿음"이라 했는데 실제로 디딤 | 83 / 153 | 159 / 167 |
    | "닿지 않음"이라 했는데 실제로 디딤 | 20 / 61 | 7 / 47 |
    | 판정과 결과가 맞은 비율 | 58% | 93% |

    - 맞지 않던 까닭 ① **바닥 같은 긴 면에서 발을 옆으로 옮기면, 발이 지금 자리에서 바로 다시 디뎠습니다**("겨눈 그 면에 닿으면 디딘다"는 규칙이 같은 면 위의 다른 자리를 구분하지 않았음). 이제 겨눈 자리에서 18px 안에 닿아야 디딥니다(`P.FOOT_LAND_R`). 이것은 조작 규칙의 수정입니다.
    - ② 다리 길이 기준이 97%로 너무 짧았습니다. 몸이 뻗는 발을 따라가므로 조금 더 먼 곳까지 닿습니다. 잰 결과(길이의 110%까지는 거의 닿고 113% 넘으면 대부분 못 닿음)로 110%로 맞췄습니다(`P.FOOT_REACH_K`). 고관절 범위로 "닿지 않음"이라 한 26번은 모두 실제로도 닿지 않았습니다.
    - 남은 어긋남 15번: "닿음"인데 못 디딘 8번(대부분 가는 중에 고관절에 막힘), "닿지 않음"인데 디딘 7번(길이 110% 근처). 판정은 "지금 자세 기준의 예상"이지 보장이 아닙니다.
- **N3 로그 시각**: 성공 로그가 결과 카드가 뜬 시각(2.858초)에 적혀, 리플레이에서 누르면 목표에 닿은 순간(2.050초)이 아닌 곳으로 갔습니다. 이제 로그는 일이 일어난 시각을 적습니다(성공 = 목표에 닿은 시각, 점프 = 발이 떨어진 순간). 재생 기록이 없는 시각의 로그는 그대로 남지만 누를 수 없고 "재생 기록 없음"으로 보입니다(고치기 전에는 눌러도 기록 끝에서 멈췄습니다).
- 물리는 바꾸지 않았습니다(v0.8.3). 여섯 시범의 성공 시각은 그대로(1.92 / 2.32 / 2.84 / 2.87 / 2.99 / 2.98초)이고 자동 시험은 모두 통과했습니다. 사람이 직접 해 본 결과는 아직 없습니다.
- 미리보기의 L·R 표시, 회색 점선, "지금 자세에서는 닿지 않음", "재생 기록 없음"의 모양과 문구는 개발 쪽이 임시로 만든 것입니다 → GPT에 디자인을 요청합니다.

## v0.16.1: 직접 디딘 발은 자동 발이 옮기지 않는다 · 물리 고관절 범위를 새 몸에 맞추는 시도(되돌림)

**발 디디기 (직접 보낸 발: 발 조종 키 + 손 입력)**
- 문제: 발이 조준점으로 가다가 **먼저 닿는 면**에 디뎠습니다. 돌출부(너비 22px)를 겨눠도 바로 옆의 가파른 바위 옆면이나 돌출부의 옆면에 먼저 닿아 거기에 디디고, 버티지 못해 떨어졌습니다.
- 고친 것 (`node test/foot_aim_check.js`, 고치기 전의 조작으로 돌리면 9개 가운데 5개 실패):
  - 조준점 둘레 30px에서 **올라설 수 있는 면(위를 향한 면)을 먼저** 고릅니다. 평평한 면이 없으면 예전처럼 가장 가까운 면입니다.
  - 위를 향한 면에는 **위에서 내려 디딥니다**(발이 그 면보다 낮고 옆에 있으면 먼저 발 자리의 조금 위로 갑니다).
  - **겨눈 그 면에 닿았을 때만** 디딥니다(가는 길에 스친 다른 면에는 디디지 않습니다).
  - 발 조종 키를 누르고 있으면 발이 디딜 자리가 보라색으로 보입니다. 어느 발도 닿지 않으면 회색과 "발이 닿지 않는 자리".
  - 보낸 발이 닿지 못한 채 멈춰 있으면 까닭을 알립니다("다리 길이보다 멀다" / "그 높이까지 다리를 들 수 없다. 몸을 더 올린 뒤 디딘다"). 전에는 아무 말 없이 발이 떠 있었습니다.

| 아래 키 설명은 화면 왼쪽에 반투명으로, 옵션으로 가리기 | 아래 띠를 없애고 플레이 구역 왼쪽에 반투명(불투명도 0.62) 세로 목록으로 옮겼습니다. **K**(키 안내, 키 설정에서 바꿀 수 있음)로 가리고 다시 보입니다. 가렸을 때는 "K 키 안내"만 작게 남습니다 |
| 차트가 왼쪽이면 키 설명은 오른쪽 | 차트 구역이 왼쪽에 붙으면 키 안내가 오른쪽으로 갑니다(과제 카드가 있으면 그 왼쪽) |

붙는 쪽·구역 크기·차트 켬끔·키 안내 켬끔은 저장되어 다시 실행해도 남습니다. **T**는 이제 차트 구역 켬·끔입니다(끄면 화면 전체가 플레이 구역, 게임 화면 100%).

**차트에 나오는 줄(액션키)**
- 차트에 기록되는 입력 동작은 아홉 가지입니다: 왼손·오른손 보내기(손 선택 2번이면 추천·다른 손), 발 조종(누른 채 손 입력), 모으기, 취소, 몸 위·아래·왼쪽·오른쪽.
- 줄은 "수행한 동작"으로 나누므로 **열 줄**이 됩니다: 왼손·오른손·왼발·오른발, 모으기, 취소, 몸 위·아래·왼쪽·오른쪽. 발 조종 키는 따로 줄이 없고 왼발·오른발 줄에 조합(발 조종 키 + 손 입력)으로 나옵니다.
- 취소 줄은 이번에 새로 넣었습니다(기록에 그때 누른 키와 함께 남습니다). 조준 키와 설정·보조 키는 차트에 넣지 않습니다.
- 가장 작은 크기: 머리줄 18 + 눈금 13 + 여백 4 + 열 줄 × 15 = **185**(논리 좌표). 이때 줄 머리 키캡의 높이는 13.5(720p에서 18px, 1080p에서 27px)입니다.
  - 줄 높이 13·14·15·16을 화면으로 견줘 보고 15로 정했습니다. 13에서는 줄 머리의 마우스 그림에서 좌·우 버튼이 구분되지 않았습니다.
  - 그래도 열 줄일 때 SPACE·L Shift 같은 긴 글자는 720p에서 약 8px입니다. 글자를 읽기보다 모양·색·자리로 구분하는 크기입니다. 줄이 적을 때(서너 줄)는 줄 높이 37~50으로 넉넉합니다.
  - 아주 작은 마우스 그림(높이 16 미만)은 눌린 버튼의 색이 보이도록 조금 넓히고 버튼 칸을 키웠습니다.

**플레이 구역**
- 게임 화면의 배율: 아래·위 붙임(185) **66%**, 옆 붙임(300) **69%**, 차트 끔 100%. 구역을 키우면 더 줄어듭니다(아래 320이면 41%).
- 게임 화면보다 플레이 구역이 넓거나 높은 쪽은 벽과 바닥이 이어져 보입니다. 옆 붙임에서는 게임 화면을 아래로 붙이고, 위에 남는 띠에 과제 카드와 키 안내를 둡니다(게임 화면을 가리지 않음).
- 조준은 화면 좌표 ↔ 게임 좌표를 한곳(`toWorld`·`toScreen`)에서 바꿉니다. 네 방향 모두 마우스 자리에 조준점이 오는지, 과제 4를 마우스로 해서 성공하는지 시험합니다.
- 게임 화면에 붙어 있던 안내(조작 설명 칸, 오른쪽 위 글, 벽의 이름표, 커서 이름표)는 게임 화면과 같은 배율로 줄어듭니다. 66%일 때 조작 설명의 글자는 720p에서 약 10px, 1080p에서 약 14px입니다. **720p에서는 읽기에 작습니다.**
- 조작 설명 칸의 글이 칸을 넘던 것(v0.8.1부터)을 항목 단위로 줄을 나눠 칸 안에 넣었습니다(글자 11.5 → 11, 세 줄 → 네 줄, 칸 높이는 거의 같음).
- 과제 카드는 플레이 구역에 다 들어가지 않으면 요령부터 접습니다. 결과 카드는 플레이 구역 안에서 몸·목표·유령·과제 카드·키 안내·오른쪽 위 글을 피해 자리를 찾습니다.
- 리플레이 도구는 플레이 구역 안, 차트 구역 쪽 가장자리에 둡니다(차트가 위면 위쪽, 그 밖에는 아래쪽).

**입력 차트**
- **기록별 시작 표식**: 입력마다 시작점 왼쪽에 고정 크기의 키 표식(그때 실제로 누른 키)을 붙이고, 짧은 선과 시작 눈금으로 정확한 시작 시각을 가리킵니다. 표식의 크기는 누른 시간과 상관없습니다. Space는 긴 키캡을 줄이지 않고 짧은 가로형 SPACE 키캡으로 그립니다.
- 줄 이름은 다시 넣지 않았습니다. 막대나 표식을 가리키면 그 기록의 설명(키, 동작 이름, 시작 시각, 누른 시간)이 나옵니다.
- 숫자는 가리킨 기록과 재생 시각 근처의 기록에만 붙습니다. "시범 ±N초"는 뺐습니다(같은 줄의 n번째끼리 맞대는 방식이라, 클릭을 한 번 더 하면 뒤가 모두 밀립니다).

## v0.10.0: 입력 UI — 키캡과 입력 비교 차트 (사용자 승인 시안 적용)

사용자가 승인한 시안 묶음(`Climb_Input_UI_Handoff_v1`)을 게임에 연결했습니다. 물리와 조작 규칙은 바꾸지 않았습니다(`physics.js`·`controls.js` 변경 없음, 여섯 시범의 성공 시각이 v0.9.2와 같음).

**세 가지를 따로 관리합니다**
| 무엇 | 어디 | 예 |
|---|---|---|
| 어떤 입력이 그 동작에 배정됐나 | `src/bind.js` (BIND) | 오른손 보내기 = 우클릭 / E |
| 키캡에 쓰는 글자와 모양 | `src/input-catalog.js` (입력 도감) | Mouse2 = 마우스 모양, ShiftLeft = "Shift" + L |
| 동작 이름과 색 | `src/action-names.js` (ACT) | sendR = "오른손 보내기", 파랑 |

- 키캡의 **모양은 실제 입력**, **색은 수행하는 동작**입니다. 오른손을 좌클릭에 배정하면 마우스 왼쪽 버튼이 파랑으로 나옵니다.
- 키를 다시 지정하면 다시 불러오지 않아도 모든 키캡이 바로 바뀝니다.
- 동작 이름은 시안의 임시 문구 대신 게임의 실제 동작에 맞춰 정리했습니다: 손발 = "~ 보내기", 몸 = "몸 위로·아래로·왼쪽·오른쪽", Space = "모으기"(떼면 던지기). 차트의 줄 이름은 결정된 팔다리(왼손·오른손·왼발·오른발)입니다.

**적용한 곳**
1. **입력 비교 차트**(T: 작게 → 펼침 → 끔)
   - 펼침: 시안의 패널. 줄마다 키캡(실제 입력) + 동작 이름. 시범 = 윤곽선, 내 입력 = 채움, 순간 입력 = 마름모, 누르고 있기 = 구간. 0초 = 첫 입력.
   - 길이와 자리는 기록의 시각으로 계산합니다. 아주 짧은 구간은 너비를 부풀리지 않고 작은 표식을 더합니다.
   - 기록이 3초보다 길면 시간축이 따라 움직이고, `,` `.` 키로 앞뒤를 봅니다(전체를 줄이지 않음).
   - 작게(접힌 상태): v0.9.1 자리의 작은 띠. 키캡 없이 동작 이름만 나옵니다(이 크기에서는 키 글자가 읽히지 않기 때문).
   - 색은 동작을 구분할 뿐 성공·실패를 뜻하지 않습니다. v0.9.2의 초록·주황(시범과 비슷한 정도)은 없애고, 시범과의 차이를 숫자로만 적습니다.
2. **아래 키 안내**(조작 D안): 왼손·오른손·왼발·오른발·모으기를 키캡 + 동작 이름 + 그 손발의 상태로. 누르면 키캡이 눌립니다(누를 때 85ms, 뗄 때 115ms. 움직임 줄이기 설정이면 바로).
3. **키 설정 화면**: 두 칸(주·보조) 모두 키캡 + 입력 이름. 비어 있으면 "미지정".

**규칙**
- 주·보조는 "둘 중 하나", 발 조합은 "함께"(+ 표시)로 구분합니다.
- 실제로 누른 칸을 보입니다: 보조 입력 Q로 왼손을 보내면 Q 키캡이 눌리고, 기록에도 Q가 남습니다.
- 손 선택 2번: 키 안내는 지금 게임이 추천한 손의 색을 씁니다. 차트는 기록에 남은 "결정된 팔다리"로 줄과 색을 정합니다. 아직 누르지 않은 손 줄은 손 색을 칠하지 않고 "추천·다른 손 입력"이라고 적습니다.
- 기록에는 손발 보내기마다 결정된 팔다리, 쓴 동작, 실제 누른 입력, 발이면 함께 누른 수정 키가 남습니다. 다시 지정해서 그 입력이 더는 그 동작의 것이 아니면 지금 설정의 키캡을 보입니다.

**아직 글자로 남은 곳**: 자유 연습의 위쪽 조작 설명 칸, 커서 옆 이름표("좌클릭 → 왼손 보내기"), 과제 카드의 아래 줄, 오른쪽 아래 최근 입력. 모두 지금 설정을 읽어 쓰는 글자입니다(키캡 그림은 아님). 옛 조작 A·B·C안은 그대로입니다.

## v0.8.1: 말이 안 되는 올라서기 제거, 한 팔 도약, 팔까지 쓰는 온몸 도약 (사용자 의견)

사용자 의견(v0.8.0 영상을 보고):
- 두 손으로 턱을 잡은 채 발을 올려 그 턱 위에 올라서는 것은 말이 안 된다. 팔 힘으로 허리까지 올라가는 것은 될 수 있다.
- 두 팔로 뛰면 못 잡는 것을 한 팔로 뛰면 더 높이 닿아 겨우 잡는 상황이 있어야 한다. 도약 타이밍에 따라 잡고 못 잡고가 갈려야 한다.
- Space만 누르면 다리로만 뛰고, S로 가라앉았다가 W를 누르며 뛰면 팔과 상체까지 쓰는 온몸 도약이 되어 더 높이 가야 한다.

**1. 손으로 잡은 턱에는 발을 올려 서지 않는다** (세 몸 모두)
- 자동 발도, Shift로 직접 보낸 발도 손이 잡고 있는 턱에는 디디지 않습니다. 직접 보내면 상태 칸에 "손으로 잡은 턱에는 발을 올려 설 수 없다"가 나옵니다.
- W를 누르면 팔 힘으로 가슴이 턱 위 64px(허리가 턱 높이)까지 올라가 팔로 버팁니다. 거기까지입니다.
- 손 간격 20~60px에서 모두 됩니다. 두 손을 한 자리에 모아 잡으면 올라가다 한 손이 미끄러져 다시 매달립니다.
- 관절 몸의 팔 최소 길이를 8 → 0으로 고쳤습니다. 8로 두면 손 간격에 따라 어깨가 손 옆에 걸려 몸이 옆으로 튕겼습니다. 고관절 바깥 범위는 150° → 130°로 되돌렸습니다(턱 위에 발을 올리려고 넓혔던 것).

**2. 한 팔 도약** (관절 몸)
- 한 손을 먼저 보내 두고(그 손으로 잡으려는 것) 뛰면, 놓는 손은 따라 뻗지 않고 그냥 놓습니다. 두 손을 다 놓기로 하면 두 손이 다 뻗습니다.
- 어깨 올림: 한 팔만 위로 뻗거나 잡으면 그쪽 어깨가 20px까지 올라갑니다(몸통이 옆으로 늘어나는 것). 두 팔을 다 올리면 2px까지만입니다. 그래서 한 팔로 뻗으면 더 멀리 닿습니다.

**3. 팔까지 쓰는 온몸 도약** (관절 몸)
- 던지는 순간 **W**를 누르고 있으면, 놓을 손 하나가 바로 놓이지 않고 팔로 몸을 끌어 올리다가 어깨가 손을 지나면 그 손으로 눌러 민 뒤 놓습니다.
- 두 손을 다 놓기로 했으면 겨눈 곳에서 먼 손이 끝까지 당기고, 가까운 손은 먼저 놓여 뻗습니다.
- 모으는 동안 **S** = 더 깊이 가라앉기(팔을 펴고 다리를 더 접음, 여유가 있을 때만), **W** = 다시 올라오기.

**결과** (`node test/joint_check.js` 6번, 위로 뛰어 잡은 가장 높은 턱. 잡고 있던 턱에서 위로 몇 px인지, 오차 없는 입력)

| | Space만 | Space + 떼면서 W | Space + S로 가라앉았다가 W |
|---|---|---|---|
| 두 팔 도약 | +185px | +205px | +205px |
| 한 팔 도약 | +195px | +220px | +220px |

- 한 팔이 두 팔보다 10px 높이 잡습니다. +190~195px 높이의 턱은 두 팔로는 못 잡고 한 팔로만 잡습니다.
- W로 팔까지 쓰면 +20~25px 더 높이 잡습니다.

## v0.7.2 (2단계 ②③④): 모으는 동안 A/D로 흔들다 제때 뛰기

## v0.6.1에서 바뀐 것: WASD 몸통 옮기기

- **W 위 · S 아래 · A 왼쪽 · D 오른쪽**(대각선 가능)을 누르고 있는 동안 붙은 팔다리가 몸통을 그 방향으로 옮깁니다. 떼면 그 자리에서 버팁니다. 키 설정에서 바꿀 수 있습니다(몸통 묶음).
- **몸 구조 안에서만 움직입니다.** 붙은 팔다리가 최대 길이의 95%를 넘거나 최소 길이에 가까워지는 쪽, 잡은 손이 미끄러질 각도(그 턱의 한계보다 10° 덜)를 넘는 쪽으로는 가지 않습니다. 막히면 몸통에 빨간 화살표와 "더 못 감 — 팔 길이 한계" 같은 이유가 뜹니다.
- 다리가 디뎌져 있으면 다리도 함께 밀어 줍니다. 근육 활성도와 관절 힘(옆으로 미는 힘) 한계는 그대로라 순간이동처럼 움직이지 않습니다.
- **턱 위로 올라서기**: 두 손으로 매달려 W를 누르고 있으면 턱걸이처럼 올라갑니다. 가슴이 손보다 높아지면 팔로 눌러 올라섭니다. 시험 자세에서 가슴이 턱 위 70px까지 올라섰습니다.
- **손으로 눌러 버티는 균형**: 올라선 자세에서 발 없이 곧게 편 팔 위에 서 있으면 옆으로 넘어갔습니다. 손목·어깨 힘으로 가슴을 손 위로 되돌리는 작은 힘(최대 0.3W)을 넣었습니다.
- **발이 천장에 디뎌지지 않게**: 아래를 향한 면에는 디딜 수 없습니다(턱 아랫면을 지나가던 발이 붙던 문제).
- **자동 발이 너무 가까운 곳을 고르지 않게**: 다리가 접히는 한계보다 엉덩이에 가까운 곳은 후보에서 뺍니다. 올라선 자세에서 자동 발이 턱 윗면을 딛게 됐습니다.
- 당겨 올라간 자세(팔이 접힌 상태)에서는 반동 표시를 띄우지 않습니다.

확인:
- 노드 시험(가정한 입력, 사람 아님): 두 손 턱 매달림에서 W 2초 → 턱 위로 올라섬 → 직접 발(Shift+우클릭) 또는 자동 발로 턱 윗면을 딛고 버팀.
- W+D(오른쪽 위)는 손 각도 한계에서 멈춥니다.
- A·S는 팔이 다 펴진 매달림 상태라 팔 길이 한계로 막힙니다.
- 실제 브라우저(`node test/intent_browser.js`, 22개 통과): W를 누른 채 가슴이 올라가고 떼면 버팀, D를 누른 채 옆으로 가거나 막힌 이유를 보여 줌.

알려진 문제:
- 팔 하나가 당기는 최대 힘이 체중의 1.3배라, 한 손 턱걸이도 됩니다(실제로는 상급자만 가능). 3단계에서 신체 수치와 함께 조정합니다.
- 올라선 뒤 W를 더 눌러도 팔 길이 한계로 멈춥니다. 일어서려면 손을 다음 홀드로 옮겨야 합니다.

## v0.6에서 바뀐 것 (1단계 다듬기: 손 선택과 입력 설정)

**1. 손 선택 방식 두 가지 (H로 바꿈)**
- **1번(기본)**: 입력마다 손이 정해져 있습니다. 커서 왼쪽·오른쪽에 "좌클릭 → 왼손 보내기"처럼 표시하고, 같은 색·같은 입력 이름의 표시를 그 손 위에도 붙입니다.
- **2번**: 게임이 추천하는 손을 누르기 전에 보여 줍니다. 추천은 커서까지 가깝고, 덜 매달려 있고, 이미 떨어져 있는 손을 고르고, 마지막 남은 손은 피합니다. 다른 손이 22점 넘게 나은 상태가 0.15초 이어질 때만 바뀌어서 커서를 조금 흔들어도 그대로입니다. 누르는 순간 그 손으로 확정합니다.
- **모으는 동안**: 표시가 "도약 때 놓기 / 놓기 취소"로 바뀝니다. 주황 고리는 도약 때 놓을 손, 하늘색 고리는 이동 중인 손입니다. 같은 입력을 한 번 더 누르면 그 손만 취소하고, X(취소)는 모두 취소합니다.

**2. 모든 입력을 바꿀 수 있는 키 설정 (Esc 또는 0)**
- 배틀그라운드식입니다. 동작 30개에 각각 두 칸이 있고, 키보드 키나 마우스 버튼(좌·휠·우·옆 버튼 두 개)을 넣습니다.
- 바꿀 수 있는 동작: 조준 이동(상하좌우·천천히), 손 보내기, 다른 손, 직접 발, 힘 모으기, 취소, 보조 켜고 끄기, 실험실 키까지 전부.
- 칸 클릭 또는 방향키+Enter로 바꾸고, Delete로 비웁니다.
- 겹치는 입력은 빨간 칸과 주의 문구로 알립니다. 기본값 복원 버튼이 있습니다.
- 바꾸면 바로 브라우저에 저장되고 새로고침해도 남습니다.
- **키보드만으로 플레이**: 방향키로 조준점이 연속 이동합니다. 누르고 있으면 220→520px/초로 빨라지고, 왼Ctrl을 누른 채면 90px/초입니다.
- 게임이 쓰는 키가 브라우저 기능(스크롤, 포커스 이동 등)으로 새지 않게 막았습니다. F5·F11·F12와 Ctrl 조합은 그대로입니다. 마우스 옆 버튼이 뒤로·앞으로 가기로 쓰이지 않게도 했습니다.

**3. 잡기 보조 범위 (B로 바꿈)**
- **커서 근처(기본)**: 커서에서 가장 가까운 잡을 곳 ±28px 구간만 초록으로 보여 주고, 손이 그 구간에 닿아야 잡습니다. 구간 밖에 닿으면 몇 px 벗어났는지 뜹니다.
- **턱 전체**: v0.5 방식입니다.

**실제 브라우저 확인** (`node test/intent_browser.js`, 10개 모두 통과): 자동 발, F로 자동 발 끄고 켜기, Shift+클릭으로 직접 발, Space 없이 클릭하면 손 보내기, Space를 누른 채 클릭하면 "던질 때 놓음", 떼면 두 손 다이노 성공, 세 점에서 오른손 멀리 잡기 성공. 스크립트가 넣은 이벤트이며 사람 손이 아닙니다.

**기존 시험**: v0.4 물리 회귀 시험 `node test/run.js` 24개, 마우스 동시 입력 `node test/input.js` 17개, A·B안 `node test/keys_browser.js` 7개 모두 통과(v0.4 물리 기준).

### v0.5에서 알려진 문제

- **잡기 보조가 많이 도와줍니다.** 겨눈 턱 어디에 닿아도 잡히므로 기존 벽의 건너편 턱은 쉽습니다. 거리를 늘리면 실패가 생깁니다(위 표). 난이도는 지형으로 조정해야 합니다.
- **D안의 한 손 반동(5번 자세)은 아직 약합니다.** Space를 흔들림에 맞춰 누르고 떼면 커지지만 7초에 약 29°입니다. A안의 다리 키로는 6초에 약 66~78°입니다. 2단계(몸통 반동 연습)에서 다룰 일입니다.
- 자동 체중 이동 때문에 손이 최대 0.2초 늦게 떨어집니다. 답답하면 G로 끕니다.
- 자동 발이 가끔 다리를 꼬거나, 디딜 곳이 마땅치 않으면 발을 늘어뜨립니다. 다리를 꼬지 않게 하는 벌점과 "너무 먼 곳은 포기" 기준은 넣었습니다.
- 숫자 키(시작 자세)와 같은 프레임에 누른 다른 키는 무시됩니다.
- 중력(1.33g)과 질량 비율, 다리 길이는 바꾸지 않았습니다. 바꾸면 기존 배치가 모두 달라지므로 따로 다룹니다.
- 근육 수치는 사람 자료의 범위에 맞춘 것이고, 그것이 재미있는지는 별개입니다.

## v0.3에서 바뀐 것

기준 조작(누르는 동안 움직이고, 떼는 순간 잡거나 디디고, 잡은 뒤에는 키 없이 유지, 스페이스로 힘주기)은 그대로입니다.

1. **마우스 동시 입력 수정.** 한 버튼을 누른 채 다른 버튼을 누르거나 떼면 두 번째 손이 무시되고 첫 손이 눌린 채 남던 문제를 고쳤습니다. 원인은 브라우저가 이런 경우를 누름/뗌이 아닌 이동 이벤트로 알려 주는데 그것을 듣지 않은 것이었습니다. 이제 매 이벤트의 "지금 눌린 버튼 전체"로 상태를 맞춥니다. 창이 포커스를 잃으면 일시정지하고, 돌아올 때 누르고 있던 버튼은 한 번 뗄 때까지 무시합니다.
2. **도약 연결(J로 켜고 끔, 기본 켬).** 발을 디딘 채 스페이스로 밀기 시작하면, 손이 아직 붙어 있는 동안은 0.15초까지 자세를 버티며 기다렸다가 손을 놓는 순간(또는 시간이 지나면) 다리를 폅니다. 손을 먼저 놓고 미는 순서도 그대로 됩니다. 손을 놓을지와 방향은 플레이어가 정하고, 속도는 발이 지형을 미는 힘에서만 나옵니다.
3. **연습 지형 조정.** 발판을 왼쪽 아래로 옮겨, 매달린 자세에서 발을 디디면 엉덩이가 발보다 가려는 쪽에 오도록 했습니다. 건너편 턱은 15px 낮췄고, 건넌 뒤 쉬는 낮은 발판을 추가했습니다. 팔 길이와 힘은 바꾸지 않았습니다.
4. **반동 연습 자세(5번).** 주변이 빈 곳에서 한 손으로 매달립니다. 손 위에 "반동 N° ▲ 커지는 중 / ▼ 줄어드는 중"과 최근 최고 각도 눈금이 표시됩니다.
5. **같은 출발점.** 세 가지 방법의 자동 시연이 모두 1번 자세(두 손 매달리기)에서 시작합니다. 발판 도약은 발판을 찾아 두 발을 올리는 것부터 합니다.
6. **일반 바위 지형.** 오른쪽 바위에는 잡는 곳 표시가 없습니다. 면이 위를 향한 정도(55° 이내)면 손이 걸리고, 가파른 옆면은 걸리지 않으며, 옆의 작은 돌출부는 잡힙니다. 걸린 뒤에는 당기는 방향이 면에서 55° 넘게 벗어나면 미끄러집니다.
7. **막 디딘 발은 가볍게 누르며 따라갑니다.** 스페이스를 쓴 뒤부터 버팀목이 됩니다(이전에는 디디자마자 뻣뻣해져 몸을 튕기거나 발이 떨어졌습니다). 발은 가까운 면 중 윗면을 조금 우선하고, 너무 빠르게 움직이는 발은 디뎌지지 않습니다.
8. **실패 안내.** 도약하면 이륙 속도·각도·손 놓기 시차와 가슴이 지나간 길이 화면에 남고, 떨어지면 "바꿀 것: 타이밍 / 발 위치 / 방향"이 한 줄로 뜹니다.
9. 방향 유지(H, 기본 끔): 힘주기를 시작한 방향을 0.2초 유지하는 비교용 선택 사항입니다.

| R | 같은 시작 자세로 즉시 다시 |

- **붙잡은 상태는 키 없이 유지됩니다.** 누르고 있어야 하는 것은 "지금 움직이는 손발"과 "힘을 주는 순간"뿐입니다.
- **여러 팔다리 동시 조작**: 누른 손발이 모두 같은 커서를 향합니다. 두 손을 함께 누르면 두 손이 동시에 떨어져 뻗습니다(도약).
- 스페이스로 당긴 팔 길이·편 다리 길이는 손을 떼도 유지됩니다(버티지 못할 힘이 걸리면 그만큼 늘어납니다).
- 화면 표시: 초록 고리 = 지금 떼면 붙는다. 주황 고리 = 닿았지만 면이 가파르다. 흰 테두리 = 붙어 있음. 노랑·빨강 테두리 = 미끄러지기 직전. 흰 원 = 그 팔다리가 닿는 범위. 반투명 = 힘이 빠진 손발.

### 해 보기

1. **반동 배우기**: `5` → A·D를 누른 채 커서를 움직여 다리를 보낸다. 눈금을 보며 커지는 리듬을 찾는다. 자동 조작기 기준으로는 (가) 몸이 오른쪽에 있을 때 다리를 왼쪽으로 보내기가 가장 크고(6초에 약 78°), (나) 아래를 지날 때 다리를 접고 양 끝에서 펴기는 약 37°까지 커진다. A·D를 놓아 다리 힘을 빼면 가장 빨리 줄어든다.
2. **발판 도약**: `1` → D를 누르고 커서를 왼쪽 아래 발판 윗면에 둔 뒤 뗀다(왼발도 A로). 발이 엉덩이보다 왼쪽에 있어야 오른쪽으로 뜬다. 커서를 건너편 턱 쪽에 두고 스페이스와 두 마우스 버튼을 누른다. 순서가 조금 어긋나도 된다.
3. **이동 중 한 손 잡기**: 날아가는 동안 버튼을 누른 채 커서를 건너편 턱 위에 두고, 초록 고리가 뜨는 순간 뗀다.
4. **안정시키기**: 다른 손을 턱 위로 옮기고, 발을 아래 발판에 놓는다.
5. **다른 길**: 큰 반동으로 바로 건너기 / 작은 반동으로 가운데 저그를 거치기 / 발판 도약. 바위와 돌출부를 쓰는 길도 열려 있다(자동 시연은 없음).

목표는 위쪽 금색 턱을 두 손으로 잡는 것입니다.

## 물리 구조(요약)

- 몸은 가슴·엉덩이·양손·양발 6개 질점입니다. 몸통은 막대, 팔다리는 최대 길이가 있는 줄이며 근육 힘에는 상한이 있습니다.
- 근육은 두 질점 사이에 크기가 같고 방향이 반대인 힘으로만 작용합니다. 공중에서는 입력을 해도 운동량과 각운동량이 보존됩니다.
- 잡은 손은 그 점에 고정되고 몸이 그 점을 중심으로 돕니다. 잡거나 놓아도 속도는 그대로 이어집니다.
- 디딘 발은 마찰 접촉입니다. 다리가 누르는 방향이 면에서 약 45° 넘게 기울면 미끄러집니다. 다리는 밀기만 합니다.
- 손은 면 종류마다 버티는 방향 한계가 있습니다: 깊은 턱 105°, 턱 75°, 바위 면 55°, 둥근 면 40°, 저그는 모든 방향. 한계를 넘겨 당기면 미끄러집니다. 확률 요소는 없습니다.
- 손발은 벽 앞을 지나다니다가 떼는 순간에만 지형과 맞닿습니다(정면에서 본 벽).
- 960Hz 고정 스텝, 위치 기반 구속. 같은 입력이면 항상 같은 결과가 나옵니다.

## 검증 결과: 무엇을 어떻게 확인했나

세 가지를 구분합니다.

**(1) 실제 브라우저 입력 검증** — Chromium에 실제 마우스·키 이벤트를 넣어 확인(`node test/input.js`, 17개 모두 통과). 사람 손이 아니라 스크립트가 누른 것입니다.

| 경우 | 결과 |
|---|---|
| 좌 누름 → 좌 누른 채 우 누름 → 좌만 뗌 → 우 뗌 | 각 단계에서 해당 손만 반응 |
| 우 누름 → 우 누른 채 좌 누름 → 우만 뗌 → 좌 뗌 | 각 단계에서 해당 손만 반응 |
| 둘 다 누른 채 창 밖으로 나가 하나씩 뗌, 다시 들어옴 | 뗀 것이 인식되고 눌린 채 남지 않음 |
| 버튼을 누른 채 포커스를 잃고, 그 사이 버튼을 뗌 | 뗀 것으로 처리, 잡고 있던 다른 손은 유지, 복귀 후 정상 |
| 포커스를 되찾으려고 누른 클릭 | 잡은 손을 놓지 않음. 한 번 뗀 뒤부터 정상 동작 |
| Q를 누른 채 포커스를 잃음 | 키가 눌린 채 남지 않음 |

수정 전 빌드에서는 같은 검사 중 10개가 실패했습니다. 포커스 상실은 헤드리스 브라우저에서 blur/focus 이벤트를 발생시켜 확인한 것이라, 실제 창 전환(Alt+Tab 등)은 직접 해 보셔야 합니다.

**(2) 자동 조작기 결과** — 물리 계산부를 사람과 같은 입력만으로 돌린 것(`node test/run.js`, 21개 모두 통과).

- 같은 출발점(두 손 매달리기)에서 세 가지 방법이 끝까지 성립하고, 마무리(목표 턱)와 실패 예 세 가지도 의도대로 나온다.
- 반동: 다리를 접었다 펴서 키우기(가만히 5° / 접었다 펴기 37°), 좌우로 보내 키우기(78°), 힘을 빼서 줄이기(78° → 27°, 다리를 뻗고 버티면 37°).
- 바위: 비스듬한 윗면에 매달리기, 가파른 옆면은 걸리지 않음, 돌출부는 잡히고 한 손으로 버팀.

도약 입력 간격 비교(`node test/tolerance.js`). 숫자는 "손 놓기가 밀기보다 늦은 시간", 음수는 손을 먼저 놓은 경우입니다.

| 조건 | 성공한 범위 |
|---|---|
| v0.2 (이전 지형, 연결 없음) | 0 ~ +0.04초 |
| v0.3 지형, 연결 끔, 커서를 위쪽에 고정 | -0.40 ~ +0.18초 |
| v0.3 지형, 연결 끔, 놓자마자 다음 턱 조준 | -0.40 ~ 0초, +0.09 ~ +0.21초 (+0.03, +0.06초는 실패) |
| v0.3 지형, 연결 켬(0.15초), 어느 쪽이든 | -0.40 ~ +0.30초 |

즉 개선의 큰 부분은 발판 위치 조정에서 나왔고, 도약 연결은 늦게 놓는 쪽 여유를 약 0.18초에서 0.30초로 늘리며 중간의 실패 구간을 없앴습니다. 오른발 위치는 발판 위 272~302px에서 성공했고 양 끝(266, 308)은 실패했습니다. 스윙으로 건널 때 놓는 각도는 35~45°에서만 성공해 여전히 좁습니다.

방향 유지(H)는 효과를 확인하지 못했습니다. 놓자마자 다음 턱을 조준해도 연결을 켠 상태에서는 이미 전 구간 성공했고, 0.2초 유지를 켜면 오히려 +0.18, +0.21초가 실패했습니다. 그래서 기본은 끔으로 두었습니다.

**(3) 사람이 직접 조작한 결과** — 없습니다. 이 빌드는 사람 손으로 플레이해 보지 못했습니다. 손맛, 난이도, 반동 리듬이 직관적인지는 직접 해 보셔야 알 수 있습니다.

## 알려진 문제

- **스윙으로 건너는 여유가 좁습니다.** 놓는 각도 35~45°만 성공했습니다.
- **접었다 펴기만으로는 반동이 약 37°에서 멈춥니다.** 큰 반동으로 건너려면 좌우로 보내는 방식이 필요합니다. 어느 쪽이 사람에게 자연스러운지는 모릅니다.
- **스윙 중 발 키를 떼면 뒤에 있는 지형에 발이 디뎌질 수 있습니다.** 빠르게 움직이는 발은 걸러 내지만, 느릴 때는 의도치 않게 디딜 수 있습니다.
- **도약 연결을 켜면 손을 붙인 채 발로 미는 동작이 0.15초 늦게 시작됩니다.** 일어서기 같은 동작에서 굼뜨게 느껴질 수 있습니다(J로 비교).
- 손발이 붙어 있는 동안에는 팔다리를 휘두르는 반작용이 몸통 회전으로 돌아가지 않습니다(공중에서는 정확히 보존). 이번 실험에서는 유지했습니다.
- 누른 손발이 모두 한 커서를 향합니다. 이번 실험에서는 유지했습니다.
- 팔다리 중간과 몸통은 지형과 충돌하지 않고, 가슴이 잡은 손을 통과할 수 있습니다.
- 바위에 걸리는지는 면의 기울기만 봅니다. 손가락이 걸리는 모서리 모양까지는 반영하지 않습니다.
- 한 화면 고정 카메라, 터치·게임패드 미지원, 체력·장비·재화·추가 스테이지 없음.
- `recordings/`에 이전 실행의 `late.webm` 등이 남아 있을 수 있습니다. 최신 실패 영상은 `jump_fail.mp4`입니다.
