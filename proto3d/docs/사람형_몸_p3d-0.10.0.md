## 2. 구조 — 제어 뼈대와 보이는 몸

물리·접촉·자세 계산은 지금까지의 제어 뼈대(21개 뼈)가 그대로 한다. 보이는 몸은 매번 그 확정된 자세를 옮겨 받는다(`src/human.js`). 그리기는 계산 상태를 바꾸지 않는다.

1. **치수를 새 몸에 맞췄다**(`rig.js`의 `BODY_HUMAN`). 쉬는 자세에서 두 뼈대의 관절이 같은 곳에 오도록 뼈 자리를 벡터로 잰 값이다(골반 기준 고관절 = (±0.089, +0.015, +0.051) 등). 물리의 몸통 계산(`climb.js`의 `torso`)도 같은 벡터를 쓴다. 쉬는 자세에서 관절 자리 차이: 무릎 1.3cm(곧은 다리라 굽는 쪽이 정해지지 않는 자리), 나머지 1mm 안.
2. **옮기는 방법**: 몸통·쇄골·목·머리 = 제어 뼈의 세계 회전 × 쉬는 자세의 차이. 팔·다리 = 새 몸의 어깨·고관절에서 제어 뼈대의 손목·발목 자리로 두 마디 IK(굽는 쪽 = 제어 뼈대의 팔꿈치·무릎 쪽). 손·발 = 제어 뼈의 회전(손가락 쪽·손바닥, 발볼 쪽·위).
3. **제어 뼈대에 없는 것은 그림에서 만든다**(모두 계산 걸음에서 정한 값만 읽는다):
   - 손가락: `S.fing`(잡음 1, 쉬는 손 0.3, 뻗는 손 0). 마디마다 70°·25°·12°까지(엄지는 절반).
   - 아래팔 비틀기: 놓인 손은 손바닥이 몸 쪽(80°, 손목과 아래팔에 나눔). 잡거나 뻗는 손은 손바닥이 팔꿈치 안쪽 쪽(잡을 때 벽을 본다).
   - 어깨뼈 리듬: 팔을 70°보다 높이 들면 쇄골 바깥 끝을 들어 올린다(머리 위 180°에서 28°). 넣기 전에는 머리 위로 든 팔에서 어깨가 구겨졌다. 어깨 관절이 제어 뼈대보다 몇 cm 올라가지만 손목은 IK가 제어 뼈대의 자리에 맞춘다.
4. **새 몸의 부피에 맞춘 물리 변경(새 몸에서만, 옛 몸은 0.9.1과 같음)**:
   - 몸통–지형 충돌: 몸 원점 둘레 원기둥(반지름 12cm) → 골반·가슴 두 원기둥(메시를 잰 상자를 따라 기울고 돈다, 반지름 12·14cm). 옛 원기둥으로는 새 몸의 골반·가슴 앞면이 벽에 4.7cm 들어갔다.
   - 제 몸 충돌의 머리·가슴·골반 상자, 팔의 굵기(`ARM_R`), 잡을 때 손목이 턱 앞에 서는 거리(`GRIP_OUT` = 팔뚝 끝 반지름 + 4mm = 5.4cm, 옛 몸 4cm)를 메시에서 잰 값으로.
   - 디딘 다리의 무릎 방향을 고를 때 무릎만이 아니라 넓적다리 세 점과 정강이 윗부분의 여유를 본다(목표 10cm, 옛 몸 6cm).
   - 발이 길다(발볼에서 발끝 9.2cm, 옛 몸 7.5cm): 발판에서는 발끝이 벽에 들지 않게 발볼 자리를 몸 쪽으로 물리고(1cm씩 12cm까지), 늘어뜨린 발도 발끝 점으로 벽을 잰다. 고치기 전에는 발끝이 벽에 6.8cm 들어갔다.

## 3. 앞·뒤·옆 모습과 기본 관절 동작(개발 쪽이 본 것)

몸 보기(`body3d.html`): 앞·옆(왼쪽)·뒤를 같은 크기·같은 거리로 한 화면에. 기본 관절 동작은 게임과 같은 길(제어 뼈대에 자세를 주고 새 몸에 옮김)로 만든 스크립트다. 키: 1 기본 관절 / 2 원본 동작(N 다음) / B 뼈대 겹쳐 보기.

| 동작 | 본 것(정지 장면과 영상) |
|---|---|
| 쉬는 자세 | 손바닥이 넓적다리 쪽. 어깨·골반 모양 정상 |
| 팔 올리기(앞·옆) | 어깨뼈 리듬을 넣은 뒤 머리 위에서 어깨가 덜 구겨진다. 옆에서 보면 어깨 덮개 메시가 아직 조금 불룩하다(메시의 정점 무게 문제로 보임 — 고치지 않음) |
| 몸통 비틀기·옆 굽히기 | 척추 셋에 나눠 돈다. 찌그러짐 없음 |
| 깊게 앉기 | 발바닥을 붙인 채 엉덩이 48cm 내림, 무릎이 발끝 쪽 바깥으로. 골반 메시 정상 |
| 낮은(30cm)·높은(55cm) 발판에 발 올리기 | 무릎이 앞·조금 바깥으로 들린다. 높은 발판에서 골반이 조금 기운다 |
| 발목 방향 | 들기·내리기 25°, 안쪽·바깥쪽 20° |
| 손가락 굽히기 | 편 손 → 쥔 손 → 쉬는 손 |

원본 동작 비교: `ClimbUp_1m`(0.67초)과 그 몸 이동 포함판(`_RM`), `NinjaJump_Start / Idle_Loop / Land`를 새 몸의 뼈에 바로 튼다(제어 뼈대·물리 없음). 일반판은 뿌리가 제자리에 있고 몸이 위로만 움직이며, RM판은 뿌리가 함께 올라간다. **게임의 실시간 등반에는 이 동작들을 쓰지 않았다**(물리가 허용하지 않는 도달을 애니메이션이 성공시키게 된다 — 지금까지의 원칙). 비교와 다음 단계(맨틀 자세의 참고)에만 쓴다. 기존 Mixamo 자료도 0.9.1과 같이 지상 동작·동작 보기에만 쓰이고, 벽 등반은 `poseClimb`(규칙 + IK)다.

  - `motion_check`의 실패: 걷기 → 달리기 → 멈춤에서 다리 뼈의 한 걸음 회전량 변화 14.0°(기준 10°). 지상 걸음의 자작 모션이 옛 다리 비율(넓적다리 0.43·정강이 0.41)에 맞춰져 있어 새 비율(0.40·0.43)에서 생긴 것으로 본다(조사 안 함). 기준을 바꾸지 않았다.
  - `wall_browser`의 실패 둘: 두 손으로 W를 눌러 오른 높이 6cm, 수동 발로 낮은 발판에 올라 W 뒤 오른손이 턱 F를 잡지 못함(오른 높이 12cm) — 5.2절의 "장면이 옛 몸 치수에 맞춰 놓인 것"과 같은 줄기다.
  - 브라우저 시험을 옛 몸(`?body=old`)으로는 이번에 돌리지 않았다(node 시험의 옛 몸 결과는 0.9.1과 같다).
- 대표 장면 영상(새 몸·옛 몸, 같은 입력·같은 카메라, 실시간 녹화): 막힘 → 복귀는 두 몸 모두 2cm·6cm 모자람으로 거부, 성공은 6.36초(새 몸)·6.33초(옛 몸)에 잡음, 중간 취소는 두 몸 모두 디디지 않고 돌아옴. 새 몸의 영상 기록에는 "머리: 턱 A 아래에 닿음"이 두 번 있다(키가 커서 머리가 턱에 닿는다). 이 환경은 소프트웨어로 그려 게임 시간이 실제 시간보다 장면마다 0.2~0.6초 늦게 흘렀다(영상의 입력·시간 칸과 결과 JSON).
- 원본 동작 영상: 일반판은 몸 이동이 빠져 있어 NinjaJump의 공중 자세가 바닥에 붙어 보이고, ClimbUp_1m은 턱 없이 튼다(턱을 놓지 않았다 — 다음 판에 1m 상자를 함께 놓을 수 있다). RM판은 뿌리가 함께 올라간다.

## 6. 남은 것

1. 넓적다리가 벽에 6cm 들어감(교차·올라선 뒤) — 엉덩이를 빼는 자세(㉮)와 함께.
2. 잡은 손가락이 턱에 3.5cm 들어감 — 손가락 끝 IK.
3. 새 몸에서 달라진 회귀 12개 중 결함일 수 있는 셋(팔–머리, 되돌려 잡기, 한 걸음 변화).
4. 어깨 덮개 메시의 불룩함(팔을 머리 위로) — 메시 정점 무게. 그래픽 쪽과 함께.
5. 대표 장면의 자세 자체(발 들기 전 → 모서리를 넘는 순간 → 디딤 → 하중을 싣고 올라감 → 다음 손)는 새 몸에서 0.9.1의 자세 계산을 그대로 보여 준다. 새 몸을 위한 자세 개선(골반·가슴·지지 다리의 연결, ㉮)은 이번에 하지 않았다.
6. 사람 확인 전부.
