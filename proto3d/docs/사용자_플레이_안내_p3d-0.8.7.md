# 첫 5~10분 플레이 안내 — p3d-0.8.7 (2026-11-21, GPT의 0.8.7 검토를 반영해 고쳐 씀)

빌드는 그대로다(p3d-0.8.7). 이 문서만 고쳤다. 지금까지의 시험·영상은 모두 **스크립트 입력(사람 손 아님)** 이다.
모두 성공할 필요는 없다. **실패한 것, 헷갈린 것, 설명을 다시 읽게 된 것, 원하지 않은 손발이 움직인 것**이 중요한 결과다.

## 1. 시작 (콘솔 입력 없음)

1. PC의 키보드·마우스로 `climb3d_mocap.html`(캡처 동작)을 브라우저로 연다.
2. **T** 를 누른다 → 작은 벽 앞에서 시작한다. 다시 벽 앞으로 가고 싶으면 언제든 T.
3. 화면 **왼쪽 위** 칸의 작은 글씨 줄이 `손 조작 1 · 눌러 보내기   발 보조 끔`인지 본다.
   - `발 보조 켬`이면 **F**, `실험: 벽 딛기 켬`이 보이면 **J**, `손 조작 2`이면 **H** 를 한 번 누른다. (지난번 설정을 브라우저가 기억한다)
   - 키를 바꿔 둔 적이 있으면 **K**(조작표)에 나오는 키를 따른다.

**첫 5분은 이 설정 하나로만 한다**: 캡처 빌드 · 손 조작 1 · 발 보조 끔 · 벽 딛기 끔. 다른 설정과의 비교는 뒤에 한다(4절).

## 2. 지금 필요한 조작

같은 칸의 셋째 줄에 **문맥**이 나온다: `지상 조작` 또는 `벽 등반`. 발을 고르는 키는 이 문맥에 따라 다르다.

| 하고 싶은 것 | 기본 입력 |
|---|---|
| 왼손 / 오른손 보내기 | 마우스 왼쪽 / 오른쪽 단추. 문맥이 지상 조작일 때 오른쪽 단추는 **짧게** 눌렀다 뗀다(길게 누르면 시점 돌리기) |
| 발 보내기 | 문맥이 **지상 조작**이면 **X** 를 누른 채 클릭 · **벽 등반**이면 **Shift** 를 누른 채 클릭 |
| 왼손 / 오른손 놓기 | Q / E |
| 발 놓기 | 그 문맥의 발 선택 키(X 또는 Shift)를 누른 채 Q / E |
| 몸 올리기 · 내리기 · 좌우(벽 등반) | W · S · A / D |
| 뛰기 | Space(오래 누르면 높이) |

**발이 바닥에 닿아 있는지가 아니라 화면의 문맥을 본다.** 손으로 턱을 잡으면 두 발이 바닥을 디디고 있어도 문맥은 `벽 등반`이다 — 그때 발은 Shift로 고른다. `시점 보기 · 조작 멈춤`이라고 나오면 **V** 로 돌아온다.

## 3. 세 가지만 해 보기

1. 턱 A(시작하면 바로 앞 머리 위에 있는 턱)를 원하는 손으로 잡고, 한 손을 다른 손 **너머로** 옮겼다가 되돌려 본다.
2. 원하는 발을 골라 발판에 디딘 뒤 몸을 올려 **다른 턱**으로 가 본다.
3. 막히면 바로 T로 다시 시작하지 말고 다른 잡는 곳·발·몸 조작을 한두 번 시도한다. 답답하면 그 순간을 적고 넘어가도 된다.

어떻게 하면 되는지는 일부러 적지 않았다. 스스로 길을 찾는지를 보려는 것이다. 막혀서 도움이 필요할 때만 6절의 힌트를 **하나씩** 읽는다.

## 4. 시간이 남으면 (선택)

- **손 조작 2**: 턱 A를 한 손으로 잡은 뒤(문맥이 벽 등반이 된 뒤) **H** 를 눌러 바꿔 본다. 누르는 동안 손이 뻗고 떼면 잡는다.
- 오른쪽의 높은 턱 B(서서는 닿지 않는다)로 뛰어 잡기.
- `climb3d.html`(자작 동작)과 견주기.

## 5. 적는 방법

한 가지마다 아래 여섯 줄이면 충분하다. 짧은 화면 녹화와 문제가 보인 시각만 있어도 좋다.

```text
설정: (예: 캡처 빌드 / 손 조작 1 / 발 보조 끔 / 벽 딛기 끔)
하려던 것:
기대한 움직임:
실제 움직임:
다시 해 본 방법과 결과:
힌트를 읽거나 들었는지:
```

- **힌트를 읽었으면 읽었다고 적는다.** 이 대화에서 이미 "막힌 뒤의 다른 길" 순서를 본 적이 있으므로, 과제 2·3은 "힌트를 읽음"으로 적으면 된다(처음 하는 사람이 스스로 찾았는지와 구분하려는 것이다).
- **이미 알려진 문제도 플레이를 방해했으면 적는다**: 팔다리가 한 순간 튀는 것, 뛰어 잡은 직후 정강이가 벽에 들어가는 것, 점프하면 공중에서 무릎을 접은 채 올라가는 것, 팔을 다 편 한 손 자세에서 교차가 막히는 것. "알려진 것"이라는 이유로 빼지 않는다.
- 이 판에 없는 것: 턱 위로 올라서기(맨틀), 코스, 키 설정 화면.

## 6. 막혀서 힌트가 필요할 때만 (하나씩)

1. 반대편으로 엇갈리는 대신, 엇갈리지 않는 잡는 곳을 먼저 잡아 본다.
2. 발판에 발을 올리고 몸을 옮겨 본다.
3. 확인된 순서 하나: 오른손을 턱 A의 엇갈리지 않는 곳으로 → 오른발을 오른쪽 아래의 낮은 발판에 → W로 몸 올리기 → 오른손으로 턱 A의 오른쪽 위에 있는 턱 F.

3번은 스크립트 입력으로 성립한 순서다. 그대로 해도 사람의 타이밍·조준·출발 자세에 따라 안 될 수 있다 — 안 됐으면 어디서 안 됐는지 적는다. "자세만 바꾸면 같은 목표가 반드시 잡힌다"는 뜻도 아니다.
