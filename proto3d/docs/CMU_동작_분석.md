# CMU 동작(ASF·AMC) 별도 분석 — 1차 (2026-11-24)

사용자가 준 등반 관련 동작 자료(피험자 01·13·14·15·40·41·81·143, 동작 파일 36개, 120장/초)를 GPT 요청 순서대로 본 결과다.
**게임 코드는 바꾸지 않았다.** 원본 재생 → 구간 분류 → 참고 동작 고르기까지이고, 캐릭터 변환과 실제 조작에서의 자연스러움은 다음 단계에서 따로 검증한다.

- 원본 자료(ASF·AMC)와 그것으로 만든 영상·그림은 저장소에 넣지 않았다(세션 임시 폴더). 저장소에는 읽기·재생·분류 도구만(`tools/cmu/`).
- 이용 조건(개발 쪽이 아는 범위, 원문은 이 환경에서 확인하지 못함): CMU 동작 자료는 연구·상업 제품에 써도 되지만 자료 자체를 되파는 것은 안 된다고 알려져 있다. 저장소에 넣을지는 사용자가 원문을 확인하고 정한다.
- 파일 이름 `.amc.txt` → `.amc`로 바꿔 읽었다(내용은 같은 형식).

## 1. 원본 재생: 단위·축·프레임률

도구 `tools/cmu/amc.py`(읽기·정방향 계산), `sanity.py`(확인), `render.py`(재생 영상).

| 항목 | 정한 것 | 확인한 방법과 결과 |
|---|---|---|
| 단위 | ASF `length 0.45` → 1단위 = 1/0.45인치 → 미터 | 다리 길이 0.74~0.89m, 머리 높이 1.54~1.69m(서 있는 첫 장) — 사람 범위 |
| 축 | y가 위 | 디딘 발 높이의 흔들림(표준편차) 0.7~1.8cm — 바닥이 평평하게 나온다 |
| 회전 | "XYZ" = Rz·Ry·Rx, 뼈 방향은 ASF 틀(axis)에서 | 굽은 무릎이 발끝 쪽으로 나간 장면 86~100% (회전 약속이 틀리면 무릎이 뒤·옆으로 꺾인다) |
| 프레임률 | 120장/초 | 01의 떨어지는 구간에서 엉덩이 가속도 −9.8~−10.4m/s²(중력과 맞음. 60장/초로 읽으면 4배 어긋난다). 13·14는 떨어지는 구간이 없어 이 방법으로는 확인하지 못함 |

- −42·−47m/s²(01_14, 41_09)는 한 구간의 튐이다(표지 점 오류로 보임 — 영상으로 확인할 것).
- **촬영 영상과의 비교는 하지 못했다.** CMU 사이트가 이 환경의 네트워크 정책에 막혀 있었고, 허용 목록에 넣은 뒤의 내려받기는 이 세션의 권한 확인에서 거부됐다. 사용자가 해당 동작의 촬영 영상(또는 CMU 목록의 동작 설명)을 주면 같은 시각을 나란히 놓고 비교한다.

## 3. 구간 분류 (자동 1차 → 눈으로 확인)

도구 `segment.py`. 자동 분류의 기준(개발 쪽이 정한 진단선):
- 발 올리기: 한 발이 멈춘 자리에서 20cm 넘게 높은 자리로 옮겨 다시 멈춤(2.5초 안)
- 체중 이동: 두 발이 멈춘 채 엉덩이가 발–발 선 방향으로 8cm 넘게
- 가슴–골반 비틀림: 20° 넘게 0.3초 / 골반 돌기: 발을 디딘 채 골반 30° 넘게
- 매달리기: 손이 어깨 위에서 멈춤 + 멈춘 발 없음(0.3초)
- 몸 끌어올리기: 2초 안에 엉덩이 20cm 넘게, 손이 어깨 위에서 잡고(50% 넘음) 발 디딤 50% 아래 / 발 디딤이 많으면 "다리로 올라서기"
- 내려오기: 2초에 30cm 넘게 내려감(손발 닿음 없는 몫이 30% 넘으면 "뛰어내리기")

눈으로 확인한 것(0.1초 간격, 정면·옆):

## 5. 다음 단계 (나눠서 검증. 물리·조작을 한꺼번에 바꾸지 않는다)

1. **원본 재생 확인**: 촬영 영상(사용자)과 같은 시각을 나란히 — 남은 일.
2. **캐릭터 변환**: 고른 구간만 우리 뼈대(제어 뼈대 21개)로 옮겨 몸 보기(`body3d.html`)에서 원본과 나란히. 손발 자리·관절 범위·관통을 따로 잰다. 실시간 등반에 틀지 않는다.
3. **실제 조작 중 자연스러움**: 변환이 맞으면 자세 기본값(가슴·골반 기울기, 발 올리는 시간 등) 하나씩만 견주는 실험 스위치로 넣고 기존 시험·영상으로 전후를 잰다.
4. 팔로 끌어올리는 장면은 이 묶음에서 찾지 못했다 — 다른 피험자 자료가 필요할 수 있다.
