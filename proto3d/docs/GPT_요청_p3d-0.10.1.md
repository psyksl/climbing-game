# GPT 전달 — p3d-0.10.1 (측정 정정 + 대표 장면의 전신 자세)

받은 검토: `Climb_p3d_0.10.0_Review.zip`. 결과 문서: `docs/사람형_몸_p3d-0.10.1.md`. 상태: **기술 반영, 시각/사람 확인 대기.** 권장 검토: GPT-6.1 Sol, 높음.

## 아직 전달하지 않은 것(판 번호별)

- **p3d-0.10.1**(이번): 관통 측정 정정과 다시 잰 비교, 뼈 무게 변환 오류, 회귀 셋의 원인과 수정, 자세 규칙 ㉮와 참고 자세 선택의 비교, 손·손가락, 어깨 원인 확인, 몸 보기 고침, 새 몸 대표 장면 다섯과 영상.
- p3d-0.9.1 문서(`docs/GPT_요청_p3d-0.9.1.md`)는 0.10.0 묶음에 함께 넣었다.

## 이번 묶음

- 실행: `climb3d.html`(기본 = 사람형 몸·새 자세 규칙. 비교: `?posture=base` = 0.10.0 규칙, `?body=old` = 옛 몸), `body3d.html`(몸 보기)
- 영상(1배속, 뒤·옆, 입력과 실제/게임 시간 표시): 새 몸 대표 장면 h1 성공 · h2 중간 취소 후 다시 · h3 막혀 실패 → 다른 목표 · h5 놓고 다시 잡기 — 새 규칙과 0.10.0 규칙. 몸 보기(기본 관절 동작, 원본 동작 + 1m 턱)
- 결과 파일: 회귀·관통·참고 비교·닿는 거리의 출력(`results/`)
- 참고 자세 방식(`?posture=ref`)은 Mixamo에서 뽑은 색인이 필요해 캡처 빌드에만 들어 있다(저장소·이 묶음에 넣지 않음). 비교 숫자는 결과 문서 5절.

## 요청 — 그래픽

1. 어깨 덮개의 구겨짐은 원본 뼈대에 위팔만 돌려도 생긴다 → 모델의 정점 무게 문제로 확인했다. 간단한 무게 다시 나누기는 나아지지 않아 껐다. 무게를 다시 칠할지(그래픽 작업), 다른 몸으로 바꿀지 판단을 요청한다.
2. 잡은 손의 모양(손바닥이 턱 앞면, 손가락이 윗면을 덮음)과 뻗을 때 미리 세우는 손 모양이 사람 손처럼 보이는지 봐 달라.

## 요청 — UI

1. 몸 보기의 아래 안내 띠와 1m 턱 표시는 개발 쪽이 임시로 만든 것이다.
2. 게임 왼쪽 위 판 줄의 "자세 새 규칙/0.10.0/참고 자세(실험)" 문구는 임시.

## 요청 — 기획

1. 자세 규칙: 기본을 ㉮ 규칙으로 두었다. 참고 자세 선택은 가장 가까운 참고 장면도 0.5~1.0m 떨어져 있어(받은 동작은 주로 매달려 오르는 자세) 실험 설정으로만 두었다. 다음 판에서 참고 자세 쪽을 더 볼지(바닥·발판에 발을 둔 등반 동작 자료가 필요해 보인다), 규칙 쪽을 다듬을지.
2. 새 몸에서 실패로 바뀐 회귀(결과 문서 5절)는 장면을 옮기지 않았다. 원래 장면은 경계 기록으로 두고, 새 몸 대표 장면(h1~h5)을 기대값으로 삼을지.
3. 두 손을 턱에 10cm 간격으로 모으는 자세는 새 몸의 굵은 팔뚝 때문에 "다른 팔에 막혀 닿지 않음"이 된다. 치수 경계로 둘지, 손을 모을 때 팔이 서로 눌리는 여유(지금 1.2cm)를 다시 볼지.

## 개발 쪽 의견

- 무릎만 바꾸는 것으로는 개구리 자세가 풀리지 않았다. 원인은 엉덩이가 벽에 너무 가까워 넓적다리가 들어갈 자리가 없는 것이었다. 엉덩이를 빼서 자리를 만드는 것이 먼저다(참고 영상 5382882의 5.0~5.4초도 같은 순서로 보인다). 다만 발판에 디딘 다리가 거의 다 접힌 동안 무릎을 크게 여는 것은 지오메트리가 정한 결과로 보고 남겼다.
- 마네킹이 두꺼워 접촉 둘레의 여러 수치(손을 모으는 간격, 넓적다리의 여유, 어깨 덮개)가 경계에 걸린다. 몸을 가늘게 바꾸지 않는다는 결정을 따랐고, 대신 각 경계를 수치로 적었다.
