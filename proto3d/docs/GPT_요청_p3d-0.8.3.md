## 2. "바로 할 일" 넷 — 한 문장씩

1. **P1-A 첫 프레임 전의 취소**: 고쳤다. 실제 DOM 이벤트로 0.8.2 빌드에서는 "뻗기 시도 1번 → 잡음", 0.8.3에서는 시도 0번·다른 손 그대로. 프레임 직후의 취소도 함께 적었다(누름 기록에 `명령 1번 → 취소: mouseleave`).
2. **P1-B 실제 팔 표면**: 판정 부피를 그려지는 굵기로 바꿨다. 같은 메시 반례(@270 · 2.03cm · 정점 171개)가 0이 됐고, 뻗는 팔의 **팔뚝** 표면은 아홉 장면 모두 0(자작·캡처). **위팔은 턱 F 장면에서 0.5cm가 남는다 — 미해결로 둔다.**
3. **P3 점프의 추진 모습**: 이륙 92ms를 그대로 두고, 발을 디딘 채 다리가 펴지기 시작해(뜨는 순간 다리 길이비 0.52 → 0.69) 뜬 뒤 0.18초에 다 펴진 다음 접히게 했다. 웅크려 걷다 뛸 때의 발 바닥 침투도 없앴다. **땅에서 다 펴고 뜨는 것은 아니다. 자연스러운지는 판정하지 않았다.**
4. **P4 증거의 시점**: 잡기 이벤트의 걸음에 적는다(@830 0.814 → **잡는 걸음 @897 0.862, 무릎각 119°** → 끝 @1201 0.857).

## 5. 요청 — 기획

1. **위팔과 몸통.** 3절의 위팔 0.5cm를 (a)에서 어떻게 풀지: 당겨 올라갈 때 가슴·어깨가 턱에서 떨어지게(몸의 층) 할지, 그 자세에서는 팔을 보내지 못하게 할지(그러면 턱 F 장면의 풀이가 달라진다). 개발 쪽 의견: 앞의 것.
2. **캡처 점프 동작.** 받은 점프 동작은 공중에서 두 발이 앞뒤로 50cm쯤 벌어진다(달리며 뛰는 모습에 가깝다). 제자리 점프에 맞는 다른 동작을 고를지 — 사용자가 받아 줄 동작의 조건을 정해 주면 된다.
3. **매달린 뒤의 남은 흔들림**(캡처 모션의 새 실패 둘). 기준(0.05m/s, 1cm)을 지킬 대상인지, 뛰어 잡은 뒤의 흔들림으로 받아들일 것인지. 기준은 건드리지 않았다.

## 6. 요청 — UI·그래픽 (지금 모양·문구는 모두 임시)

1. "팔 경로 막힘"의 자리·기호, 팔꿈치가 도는 동안의 작은 진행 표시.
2. 발 선택을 누르면 마우스 키캡이 왼손/오른손 → 왼발/오른발로 바뀌는 표시(기존 인계 자산으로). 지금은 미리보기 글이 손 → 발로 바뀔 뿐이다.
3. 진단 표시 "하중 0.09 / 한계 0.65"의 플레이 화면용 축약. 다리는 한계가 축 방향 몫이라 옆 몫이 더해지면 하중이 한계보다 크게 보일 때가 있다 — 어떻게 적을지.
4. 취소 알림(0.9초, "⤺ 오른손 보내기 취소")은 그대로다. 다시 입력하면 사라진다.

## 8. 한계

- 시험·영상·그림은 모두 스크립트 입력이다. "실제 입력"은 헤드리스 브라우저의 키·마우스·DOM 이벤트이며 사람 손이 아니다.
- `arm_mesh`는 뻗는 팔만 통과·실패로 본다. 잡고 있는 팔은 자료로만 적었고(이 장면들에서 0.00cm) 다른 자세는 보지 않았다.

- 점프의 다리 길이비 표는 계산 값이다. 발목 밀기(뒤꿈치 들림)는 확인하지 않았다.
