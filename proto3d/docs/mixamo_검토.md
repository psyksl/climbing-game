# Mixamo 동작 묶음 검토 (2026-11-19, 사용자가 올린 분할 압축 11조각)

조사한 범위: 올려 주신 파일 전부를 풀어 three.js의 FBX 읽기 도구로 읽고 잰 것입니다. 영상으로 하나하나 본 것은 아닙니다(걷기·달리기·서 있기 세 동작만 이 시제품 캐릭터에 옮겨 화면으로 확인).

## 1. 받은 것

- 조각 11개(`motion.z01`~`z10` 각 25MB + `motion.zip` 20MB)가 모두 왔고, 합쳐서 오류 없이 풀렸습니다. 풀면 402MB.
- FBX 219개 + 묶음 zip 4개(Action Adventure / Locomotion / Male Locomotion / Female Basic Locomotion Pack, 안에 FBX 60개).
- 바깥 FBX 219개는 **모두 읽혔습니다.** 형식이 한 가지로 같습니다.
  - FBX 7.7(바이너리), 뼈 65개(`mixamorig` 접두어), 초당 30장, 동작 트랙 53개(뼈 52개의 회전 + 엉덩이 위치).
  - 캐릭터는 X Bot(메시 `Beta_Surface` + `Beta_Joints`). 204개에는 스킨이 들어 있고 15개(주로 Walking 계열)는 뼈대만 있습니다.
  - 길이 단위는 cm, 캐릭터 앞 = +z, 왼쪽 = +x, 쉬는 자세 = T자. 키(머리 끝) 182cm, 넓적다리 44.4·정강이 44.5cm.
- 묶음 zip 안의 60개 중 **20개는 읽기 도구가 읽지 못했습니다**("Unknown property type"). 같은 FBX 7.7인데 일부 파일의 속성 형식을 three.js 0.187의 읽기 도구가 모릅니다. 읽힌 40개는 초당 5~30장으로 섞여 있고(줄여서 내보낸 것) 바깥 219개와 겹치는 동작은 없습니다. 지금 쓰려는 동작은 바깥 219개에 다 있어 묶음은 쓰지 않았습니다.

## 2. 내용

| 분류(이름으로 나눔) | 서로 다른 동작 수 |
|---|---|
| 등반·매달리기(Braced Hang, Free Hang, Shimmy, Climbing, Rope, Ladder, Wall, Swing …) | 86 |
| 걷기·달리기(Walking, Running, Sprint, Strafe, Turn, Stairs …) | 66 |
| 서 있기·일어서기(Idle, Standing, Crouch …) | 38 |
| 점프·낙하(Jump, Falling, Landing …) | 19 |
| 기타 | 5 |

- 파일 219개 = 서로 다른 동작 214개 + 값이 완전히 같은 중복 5개.
- 이름 뒤에 `(1)`, `(2)`가 붙은 것은 대부분 **중복이 아니라 좌우를 뒤집은 것**입니다(길이가 같고 옆 이동만 반대인 쌍이 74쌍). 일부는 같은 이름의 다른 동작입니다(예: `Climbing`~`Climbing (11)`은 길이·이동이 서로 다른 동작, `Idle`~`Idle (7)`도 마찬가지).
- 거의 모든 동작에 **몸의 이동이 들어 있습니다**(제자리 옵션이 아님). 예: Walking은 1.03초에 184.5cm, Running (4)는 0.7초에 306cm.
- 전체 목록과 잰 값(길이, 이동, 평균 빠르기, 엉덩이 높이 범위, 첫·끝 자세 차이, 스킨, 값이 같은 다른 파일): `mixamo_목록.csv`(219줄).

## 3. 바로 쓸 수 있는 것과 아닌 것 (개발 쪽 의견)

**바로 쓸 수 있다 → 이번에 적용함 (p3d-0.2.0)**
- 지상 이동의 서 있기·걷기·달리기. 고른 것:
  - 서 있기 `Idle (4)`(3.3초, 반복)
  - 걷기 `Walking`(반복, 원본 1.79m/s → 이 캐릭터로 옮기면 1.69m/s, 한 주기 1.74m)
  - 달리기 `Running (4)`(반복, 원본 4.38m/s → 4.14m/s, 한 주기 2.90m). 조작의 달리기 속도 4.2m/s와 거의 같습니다.
- 고른 까닭: 첫 장과 끝 장의 자세가 같아 반복되고, 속도가 조작 속도에 가깝습니다. `Walking (2)`는 한 발이 닿아 있는 몫이 0.85로 끄는 걸음이어서 뺐습니다.

**쓸 수 있지만 손이 더 간다 (아직 하지 않음)**
- 점프·착지·웅크림(`Jumping`, `Jumping Up`, `Falling To Landing`, `Crouching Idle`): 지금 점프는 누른 시간에 따라 높이가 달라져 동작 길이를 물리에 맞춰야 합니다. 지금은 자작 동작이 맡습니다.
- 뒤로 걷기·옆걸음·제자리 돌기: 지금 조작은 가는 쪽으로 몸을 돌리므로 당장 쓸 데가 없습니다.

**그대로는 쓰면 안 된다 (등반)**
- 등반·매달리기 86개는 "정해진 벽·정해진 턱에서 정해진 거리만큼" 움직이는 동작입니다(예: Braced Hang Shimmy는 1.17초에 옆으로 59cm, Climbing Up Wall은 2초에 126cm 위로).
- 이 게임의 등반은 손발이 실제로 닿는지·버티는지를 물리가 정합니다. 동작을 그대로 틀면 "물리가 허용하지 않는 도달을 애니메이션으로 성공시키는" 것이 됩니다.
- 쓸 곳: ① 자세의 기준(매달린 자세, 발을 벽에 댄 자세, 손을 옮길 때 몸통·골반이 어떻게 따라가는지), ② 관절 각도 범위와 동작 시간표, ③ 물리가 정한 손발 자리에 맞춰 자세를 고르는 재료(W2에서 손 IK와 함께).

## 4. 이용 조건

- 이 환경에서는 Adobe의 FAQ 페이지(`helpx.adobe.com`)가 네트워크 정책에 막혀 원문을 직접 읽지 못했습니다. 검색 결과(Adobe 커뮤니티의 FAQ 옮김 글)로 확인한 내용: 개인·상업 프로젝트(게임 포함)에 쓸 수 있다, **원본 캐릭터·동작 파일을 따로 나눠 주는 것은 안 된다.** 원문은 사용자가 한 번 확인해 주세요.
- 이 저장소(`psyksl/climbing-game`)는 **공개 저장소**입니다. 그래서:
  - 원본 FBX와, 그것을 옮긴 동작 값(`assets_local/clips.json`), 그 값이 들어간 빌드(`climb3d_mocap.html`)는 **저장소에 넣지 않았습니다**(`.gitignore`).
  - 저장소에는 변환 도구(`tools/mixamo_convert.mjs`)와 재생 코드만 있습니다. `climb3d.html`은 전처럼 자작 동작만 들어 있습니다.
  - 캡처 동작이 든 빌드는 사용자에게 파일로 직접 드립니다.
- 넣어도 된다고 사용자가 정하면(저장소를 비공개로 바꾸거나, 조건을 확인한 뒤) `.gitignore` 두 줄만 빼면 됩니다.

## 5. 다시 만드는 법

```
node tools/mixamo_convert.mjs <FBX를 푼 폴더> assets_local/clips.json   # 목록은 tools/mixamo_clips.json
node build.js                                                          # climb3d.html + climb3d_mocap.html
```
