## 3. 요청 — 영상 관찰 (GPT 계획의 단계 A·B, `05` 양식)

**왜 GPT에 부탁하는가**: Claude 쪽 환경에서는 유튜브가 재생되지 않는다. 위키미디어 공용의 영상은 받을 수 있으나 한 번에 조금씩만 받아진다(지금까지 한 편). 관절 자동 추정은 그 한 편에서 믿을 수 없었다(겹쳐 보니 팔다리가 틀림). 그래서 **사람 눈으로 본 구간 기록**이 지금 가장 쓸모 있다.

**적는 법**
- `05_MOTION_ANALYSIS_TEMPLATE.md`의 1절(출처와 범위)과 2절(전 과정 표)을 그대로 쓴다.
- 각도를 숫자로 지어내지 않는다. 대신 아래 **등급**으로 적는다. 모르면 "안 보임".
  - 무릎·팔꿈치: 폄 / 조금 굽힘 / 90°쯤 / 깊이 접음
  - 발 높이: 무릎 아래 / 무릎 / 엉덩이 / 엉덩이 위
  - 발 간격: 모음 / 어깨 너비 / 그 두 배쯤 / 더 넓게
  - 몸통 방향: 벽을 정면으로 / 반쯤 돌림 / 옆으로 섬
  - 엉덩이와 벽: 붙음 / 주먹 하나쯤 / 팔을 편 만큼 떨어짐
  - 시간: 영상 시각의 차이로(초, 0.1초 단위면 충분)
- 칸마다 관찰 / 추정 / 안 보임을 구분한다.
- 동작마다 대표 구간 하나 + 다른 풀이나 실패 하나면 충분하다. 못 본 것은 빈칸으로 둔다.

**볼 것 (우선순위 순. 괄호는 그 관찰이 게임에서 정하는 것)**

A. **벽을 디딘 매달림** — 두 손으로 턱이나 큰 홀드에 매달려 쉬는 장면
 1. 발이 벽이나 발 자리를 디디고 있는가, 늘어뜨리고 있는가. 수직 벽과 오버행에서 다른가. (두 손 매달림의 기본 자세)
 2. 무릎 굽힘, 발 높이, 발 간격, 엉덩이와 벽의 거리, 팔이 펴져 있는가. (자세 목표)

B. **높은 발 → 엉덩이 옮기기 → 다리로 일어서기 → 손 뻗기**
 3. 네 단계의 순서와 각 단계의 시간. 손이 떠나는 때가 다리가 다 펴지기 전인가, 다 펴진 때인가. (손 뻗기와 일어서기의 연결)
 4. 엉덩이를 발 위로 옮길 때 몸통이 얼마나 도는가(정면 / 반쯤 / 옆으로). 뻗는 손과 같은 쪽 엉덩이가 벽에 붙는가, 반대쪽인가. (골반·몸통 방향)
 5. 발을 올리기 전에 남는 발 쪽으로 몸이 먼저 가는가. (준비 동작. 문헌은 수직 벽에서 그렇다고 한다)

C. **발 선택이 결과를 바꾸는 장면** — 같은 손 배치에서 발을 바꾸거나 다른 발을 쓰는 풀이
 6. 발을 바꿀 때의 순서(한 발을 붙이고 다른 발을 떼는가, 뛰어 바꾸는가)와 시간. (발 교대 동작)
 7. 자유 다리의 자리: 뻗는 손의 반대쪽으로 뻗는가, 뒤로 넘기는가, 벽에 대는가, 늘어뜨리는가. 그때 골반 방향. (플래깅을 모양만이 아니라 효과로 만들 때의 기준)

D. **도약(다이노)과 다시 잡기** — 대회 영상이 좋다
 8. 가라앉는 횟수와 깊이(한 번인가 여러 번인가). 가라앉기 시작부터 발이 떨어질 때까지의 시간. (사용자 결정은 "즉시 점프, 모으기 없음"이다. 벽에서도 그대로 둘지의 근거)
 9. 발과 손이 떠나는 순서. 한 손이 남는 경우와 두 손이 다 떠나는 경우를 나눠서. (지금 "손을 남긴 갈아 잡기"와 "두 손을 놓는 재잡기"의 구분)
 10. 잡은 뒤: 다리가 몇 번 흔들리고 멎는가, 다리를 접는가 편 채인가, 발을 다시 붙이기까지의 시간. (잡은 뒤의 흡수 자세)

E. **발이 떨어져 매달린 뒤의 흔들림, 일부러 만드는 반동**
 11. 다리를 언제 접고 언제 펴는가(가장 낮은 곳을 지날 때 / 끝에서). 몇 번에 멎거나 커지는가. 한 번 오가는 시간. (반동을 "다리를 접었다 펴는 진자"로 바꾸려는 안의 확인)

F. **놓치고 떨어짐**
 12. 손이 떨어진 직후 팔·다리의 모양, 몸이 도는가, 착지 자세(두 발 / 뒤로 구름 / 손을 짚음), 일어나기까지의 시간. (낙하·착지 자세)

## 4. 요청 — 기획

1. **두 손으로 매달리면 발이 저절로 벽을 디디게 할지.** 사람의 기본 자세가 그렇다(문서 11절). 그러나 "발은 사용자가 고른다"는 방침과 닿는다. 개발 쪽 안: 저절로 대는 것은 벽면에 "기대는" 것까지(하중을 조금만 받는 쉬는 자세), 발 자리(턱·발판)에 올리는 것은 사용자가 고른다.
2. **"몸 위로"(W)의 뜻.** 영상에서는 다리가 올린다. 안 ①: W는 "지금 붙은 손발로 낼 수 있는 만큼 올라간다"로 두되 디딘 발이 있으면 다리가 먼저 일하게 하고 자세가 그것을 보여 준다(조작은 그대로). 안 ②: "발을 올리고 → 그 위로 옮기고 → 일어선다"를 사용자가 단계로 조작한다(지금도 발 보내기 + A/D + W로 할 수 있으나 자세가 받쳐 주지 않는다). 개발 쪽 의견: ①을 먼저.
3. **B1**: 땅에서 발 지정을 "서 있고 이동 입력이 없을 때만 달리기 키 + 클릭"으로 좁히는 안, 또는 발 지정 키를 달리기와 떼는 안.
4. **반동의 입력**: 지금 A/D(옆으로 미는 근사). "다리 접기·펴기"로 바꾸면 어떤 키로, 누르는 동안 접는지 한 번 누르면 접었다 펴는지. 3절 E의 관찰을 보고 정하면 좋다.
5. **너그러움의 자리**: 닿는 거리·관절 범위는 넓히지 않고, 잡는 시간 창·지나친 턱 기억·조준 반경에 둔다는 안(문서 5.4절). 기본으로 둘지 옵션으로 둘지.
6. **얕은 턱**: 약 1cm 턱(손 첫 마디, 발끝)을 허용하되 균형·잡는 방향으로 어렵게(문서 6절). 사용자 의견 ⑤에 대한 답이다.
7. **화면 기본값을 발 직접 선택으로 바꿔 시험할지**(GPT 권고). 사용자 결정 대기.
