# Blender 캐릭터·리그 편집 환경 확인 (p3d-0.11.6 뒤, 2026-11-23)

사용자 지시(2026-11-23, 0.10.4 때): "Blender 캐릭터·리그 편집 환경 확인(현재 마네킹: 손목 축·손가락 굽힘·어깨 무게, 자세별 변형, 재반입 시 뼈 이름·축·크기·접촉 유지) → 그 뒤 Tripo 후보 하나를 같은 입력·장면에서 비교." 0.11.0 때 "이 작업 뒤"로 미뤘고, 0.11.6 뒤 사용자 "다음 단계로 넘어가 보자"로 시작했다.

상태: 개발 환경 확인 끝. Blender로 만든 결과를 게임 기본에 넣지 않았다(어깨 평균 무게 편집은 기본에 넣지 않는다는 0.10.3의 GPT 결정 그대로).

## 1. 환경

- 이 환경에는 Blender 프로그램이 없다. Blender를 파이썬 모듈로 받는 `bpy` 5.3.0(= Blender 5.3.0)을 세션 임시 폴더의 가상 환경에 받아 화면 없이 돌렸다(`pip install bpy==5.3.0`, Python 3.13).
- 원본: `UAL2_Standard.glb`(Quaternius, CC0 — 지금 마네킹을 옮겨 온 파일. 저장소에 넣지 않는다). 세션 임시 폴더에만 있다(세션이 바뀌면 다시 받아야 한다).
- 도구(저장소): `tools/blender/` — `inspect.py`(불러와 요약), `edit_shoulder.py`(편집 없이 다시 내보내기 `none` / 어깨 무게 다듬기 `smooth`), `edit_roll.py`(왼손·손가락 뼈 roll 30°), `compare.cjs`(human_data 두 개를 값으로 견줌), `dump_hand.mjs`(장면에서 마네킹 손 정점의 세계 자리). 결과: `results/blender/`.
- 흐름: Blender에서 불러옴 → (편집) → GLB로 내보냄 → `tools/quaternius_convert.mjs`(지금 쓰는 변환기 그대로) → human_data → 기존 시험.

```bash
python -I tools/blender/edit_shoulder.py -- UAL2_Standard.glb out.glb none
```

```bash
node tools/quaternius_convert.mjs out.glb UAL2_Standard_RM.glb out.json
```

## 4. 손목 축·손가락: 뼈의 roll을 바꿔도 되는가

- Blender에서 왼손과 왼손가락 뼈 21개의 roll을 30° 바꿔(뼈의 자리·방향은 그대로, 지역 축만 돎) 내보냈다. 쉬는 회전은 30° 다르게 들어온다(자식 뼈의 지역 자리도 달라짐 — 세계 자리는 같다).
- 장면 h1(왼손이 턱 A를 잡고, 오른손을 뻗음, 9초)을 0.25초마다 돌려 마네킹 왼쪽 아래팔·손·손가락 정점(3,119개)의 세계 자리를 견줬다: **가장 큰 차이 0.04mm.** 우리의 리타게팅은 제어 뼈대의 세계 회전을 쉬는 자세 기준으로 옮기므로 Blender의 뼈 축에 매이지 않는다.
- 주의: Blender에서 roll을 바꾸면 파일 안의 동작(손을 움직이는 키)은 보정되지 않아 뜻이 바뀐다. 게임의 등반은 이 동작을 쓰지 않는다(몸 보기의 비교 재생만 쓴다).

## 5. 어깨 무게를 Blender에서 다듬어 보기

- 방법: 시험의 "어깨 둘레"와 같은 정의(쇄골·위팔·가슴 뼈 무게가 0.08 넘게 둘 이상 섞인 정점, 왼쪽 168·오른쪽 165개)를 골라 그 세 무리의 무게만 Blender의 무게 고르기(factor 0.5, 3번)로 다듬고, 정점마다 4개로 줄여 합을 1로 맞췄다.
- 결과(정해 둔 자세·장면, 사람 확인 아님):

| 자세 | 지금 (찌그러짐 · 접힘) | Blender로 다듬은 무게 |
|---|---|---|
| 실제 장면 7순간(h1·reach3·m1) 합 | 40 · 15 | 26 · 7 |
| 원본 리그 내림 / 앞 90° / 머리 위 | 8·0 / 4·3 / 7·0 | 6·0 / 5·2 / 1·0 |
| 원본 리그 가슴 앞 교차 | 8 · 11 | 11 · 5 |

- 0.10.2에서 시험 안에서 해 본 무게 편집(이웃 평균 3번)과 거의 같은 결과다. 실제 장면에서는 줄고 가슴 앞 교차에서는 찌그러짐이 는다. 가까이 찍은 그림(h1 0.9~1.6초, 왼쪽 어깨 뒤·옆)으로는 두 무게의 차이가 거의 보이지 않았다.
- 0.10.3의 GPT 결정("어깨 평균 무게 편집은 기본에 넣지 않는다")대로 기본에 넣지 않았다.

## 6. 알게 된 것

- Blender를 이 환경에서 화면 없이 쓸 수 있고, 지금 변환기·시험과 그대로 이어진다. 무게·뼈 축·메시를 Blender에서 고친 뒤 같은 시험으로 전후를 잴 수 있다.
- 지금 마네킹의 어깨 문제는 무게 고르기만으로는 크게 나아지지 않는다(0.10.2와 같은 결론). 더 하려면 어깨 둘레의 메시 모양(덮개)을 고치거나, 교정 모양(shape key — 팔 각도에 따라 정점을 미리 만든 모양으로 옮기는 것)을 넣어야 한다. 교정 모양은 Blender에서 만들 수 있지만 지금 변환기·그리기가 shape key를 옮기지 않는다(개발 쪽 의견: 필요하면 변환기와 human.js에 넣을 수 있다).

## 7. 다음: Tripo 후보 비교

- Tripo는 인터넷의 3D 생성 서비스라 계정(유료일 수 있음)이 필요하고, 이 환경에서는 쓸 수 없다. 사용자가 Tripo에서 사람형 캐릭터 하나를 만들어(가능하면 리그 포함, GLB 또는 FBX) 파일을 주면, 같은 흐름(Blender → 뼈 이름을 지금 리그에 맞춤 → 변환기 → 같은 장면·시험)으로 지금 마네킹과 견준다.
