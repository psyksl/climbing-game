# 직접 해 보기 안내 — p3d-0.15.7 (발을 직접 고르는 짧은 구간)

2026-11-28 · Claude(개발). 0.15.6을 직접 해 보신 결과(해 보기 설정이 가장 할 만함 · 계속 끊기며 느림 · 발 보조는 기본 끔)를 반영한 판이다. **이 판은 아직 사람이 해 보지 않았다.** 아래의 "되는 것"은 스크립트가 넣은 입력으로 본 것이다.

## 1. 여는 법

| 파일 | 설정 |
|---|---|
| `climb3d_mocap_p3d-0.15.7_해보기.html` | **해 보기 설정**(전신 연결 + 뻗기 전 검사 + 자동 이동 보호) + **발 보조 끔**. 이 파일 하나만 있으면 열린다(0.15.6과 달리 다른 파일이 같은 폴더에 없어도 된다) |
| `climb3d_mocap_p3d-0.15.7_해보기_발보조켬.html` | 같은 설정에 발 보조만 켠 것(0.15.6의 해 보기와 같은 조합) — 견주어 볼 때 |

열면 초록 코스의 시작 자리에 선다. **T** = 시작 자리로 다시(실패하면 바로 T).

## 2. 조작

| 하려는 것 | 입력 |
|---|---|
| 손 보내기 | 턱을 겨누고 **좌클릭 = 왼손 / 우클릭 = 오른손** |
| **발 디디기(이제 직접)** | **Shift를 누른 채** 발판을 겨누고 좌클릭 = 왼발 / 우클릭 = 오른발 |
| 몸 올리기 · 옆으로 | **W** / A · D (누르고 있는 동안) |
| 손 놓기 | Q = 왼손 / E = 오른손 |
| 발 보조(자동 발) 켬·끔 | **F** — 켜면 발이 알아서 따라온다(초보자용. 기본은 끔) |
| 조작표 펼치기 | K |

## 3. 달라진 것

- **계산이 가벼워졌다.** 같은 입력을 다시 틀어 재면 등반 중 계산 한 걸음이 평균 7~9ms → 2.4~2.7ms다(이 기계). 0.15.6에서 느끼신 끊김이 줄었는지가 이번에 가장 보고 싶은 것이다.
- **발 보조가 꺼진 채 시작한다.** 발을 디디지 않고 W만 누르면 몸이 거의 올라가지 않는다. 발판을 골라 디디고 W를 눌러야 한다.
- 한 발로 올라선 채 가만히 있으면 디딘 발이 떨어지던 것, W를 떼는 순간 잡고 있던 손을 놓치던 것, W를 누르는 동안 먼저 잡은 손이 명령 없이 풀리던 것을 고쳤다(해 보기 설정에서).

## 4. 구간과 순서

초록 **시작 1·2**(두 손) → **초록 3·4** → **초록 5** → **초록 6에 두 손**. 발판은 초록 발 1~4.

스크립트 입력으로 끝까지 간 순서(손 3·4를 잡은 뒤):

- **가**: 왼발 발1 → W → 오른발 발2 → W → 왼손 5 → 오른손 6 → 왼발 발3 → W → 오른발 발4 → W → 왼손 6 (발 넷을 모두 직접)
- **나**: 오른발 발2 → W → 왼발 발3 → W → 왼손 5 → 오른손 6 → W → 왼손 6 (발 둘만)

순서는 정해져 있지 않다. 다른 순서도 해 보시면 좋다.

## 5. 알고 있는 것(미리)

- **발판이 너무 높으면 "다리가 그렇게는 올라가지 않음"으로 거부된다**(지금 서 있는 높이에서 40cm쯤 넘는 발판). 그럴 때는 W로 몸을 먼저 올린 뒤 다시 디딘다.
- 몸이 올라가면 낮은 발판에 디딘 발은 저절로 떨어진다(다리가 닿지 않게 되어서). 떨어진 발은 다음 발판에 다시 디딘다.
- 한 발로 서 있을 때 골반이 크게 돌아가고 무릎이 안쪽을 향하는 자세가 나온다 — 모양은 손대지 못했다.
- 손이 닿지 않으면 "지금은 손이 닿지 않아요."가 뜨고 손은 그대로 붙어 있다. W로 몸을 올린 뒤 다시 누른다.

## 6. 보고 싶은 것

1. **끊김·느림이 줄었는가.** 여전하면 F2 → I를 누르면 왼쪽 위 "실행" 줄에 fps · 가장 긴 프레임 · CPU 계산 시간이 나온다. 그 줄을 알려 주시면 원인을 가를 수 있다.
2. 발을 직접 고르는 것이 할 만한가, 뜻이 있는가(너무 번거롭지는 않은가).
3. 실패했을 때 까닭을 알겠는가.
4. 몸이 이상하게 보이는 때.
