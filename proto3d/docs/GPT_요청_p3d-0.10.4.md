## 요청 — 기획

1. 팔을 머리 위로 올리는 첫 잡기가 약 0.11초 늦어졌다(어깨를 돌아가는 길 + 받쳐진 뻗기 8rad/s). 뛰는 중은 12rad/s. 이 값들(실험값)을 기준으로 둘지.
2. 입력 없이 1.34초 뒤 바닥 발이 "다리가 닿는 범위를 벗어남"으로 저절로 떨어진다(체중 이동이 아님). 그대로 둘지, 골반 층이 바닥 다리를 늘리지 않게 할지.
3. 혼자 선 턱을 앞에서 끝 옆면으로 잡으면 모서리 방향으로 당겨져 미끄러진다(기존 규칙). 옆으로 당기는 잡기를 넣을지(지난 결정: 넣지 않음 — 유지하면 답 불필요).
4. 모서리 이동 순서(A2 끝 → B1 → D로 돌아감 → 발 → B1 두 손)를 사람이 찾을 수 있는지 플레이로 볼 장면으로 쓸지.

## 요청 — 그래픽

1. 끝 옆면을 잡은 손이 옆면을 감싸지 않고 윗면에 엎어져 보인다(손 확대 그림). 끝 옆면의 손 모양 시안(손바닥이 옆면을 보는지, 손가락이 윗면을 덮는지).
2. 다른 벽 시험 지형의 색·표시는 개발용 임시.

## 요청 — UI

1. 거부 문구 "손목이 그쪽으로 꺾이지 않음"(새), "손이 가는 길이 막힘"은 임시 문구.

## 개발 쪽 의견

- 팔 경로는 "속도 제한"이 아니라 "어깨 둘레에 들어가지 않는 길 + 막히면 그 자세를 지킴"으로 바꿨다. 기본의 벽 시험 결과를 하나도 바꾸지 않고 들어갔다. frame에서는 다섯 항목이 깨져(원인 넷으로 갈림) frame을 기본으로 올리려면 따로 맞춰야 한다.
- 손 접촉은 판정 쪽(틀·손목 한계·손 자리)을 연결했지만 그림의 끝 옆면 손 모양은 아직이다. 측정에 손바닥 방향을 넣는 것이 먼저다.
- 사용자 요청(별도): 다음 단계로 Blender 캐릭터·리그 편집 환경 확인 — **이번 반송에서는 시작하지 않았다.** 환경 확인 한 가지만: 이 개발 환경에 Blender는 없고, `pip`로 `bpy` 5.3.0을 받을 수 있는 것까지 확인(설치·실행은 하지 않음).
