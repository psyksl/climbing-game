# 사진의 경로를 직접 가 보기와 단계별 여유 (p3d-0.12.4)

2026-11-25. 사용자: "내가 보내 준 사진의 화살표 방향대로 갈 수 있어? 난 못하겠어서. 할 수 있다면 영상으로, 안 되면 실패한 영상을." → "단계별 여유도 재 줘. 저 연습용 자체가 난이도가 너무 높다. 대충 해도 될 정도여야 한다. 맵이 어려운 게 아니라 컨트롤이 너무 세밀하고 완벽한 포인트를 집어야 한다."

모든 결과는 **스크립트 입력(사람 손 아님)**, 캡처 동작, 화면 기본 설정(새 자세·잡기 보정·자세 보조·발 보조 켬, 벽 딛기 끔, 손 조작 1)이다. 겨눈 곳(look)은 마지막으로 보낸 목표를 넘겼다.

## 1. 경로

사진의 화살표를 지형 자료에 맞추면: 넓은 발판 → 턱 A → (턱 F) → 턱 B → 턱 C → 턱 D → 턱 E.

| 단계 | 한 일 | 끝(게임 시간) |
|---|---|---|
| 1 | 넓은 발판 위에 서서 오른손 → 왼손으로 턱 A | 3.3초 |
| 2 | 턱 A를 따라 오른쪽으로(손 옮기기 넷, 몸 오른쪽 D 셋) | 11.0 |
| 3 | 왼발을 낮은 발판에, 위로(W) 1초, 오른손 → 턱 F | 17.7 |
| 4 | 몸을 오른쪽으로(D), 왼손도 턱 F | 20.9 |
| 5 | 오른발도 낮은 발판에, 위로(W) 1.25초, 오른손 → 턱 B의 왼쪽 끝 | 27.2 |
| 6 | **발판에서 위로 뛰며(Space) 왼손 → 턱 C**(잡기 보정 18cm · 반동) | 29.5 |
| 7·8 | 오른손도 턱 C로, 왼손을 오른쪽으로 모음(두 손으로 매달림) | 34.5 |
| 9·10 | 오른손을 아래 턱 B로, 왼손도 턱 B로(몸이 내려감) | 40.5 |
| 11 | 턱 B를 따라 오른쪽으로(매달려 손 옮기기 넷) | 48.5 |
| 12 | **매달린 채 위로 뛰며 오른손 → 턱 D**(잡기 보정 10cm · 반동) | 51.1 |
| 13 | 왼손도 턱 D로, 턱 D의 오른쪽 끝까지 | 57.1 |
| 14 | 오른손 → 턱 E, 왼손 → 턱 E(두 발은 바닥) | 64.6 |

- 끝까지 간다. 입력 `test/route_steps.mjs`, 확인 `MODE=clip node test/route_try.mjs`, 영상 `MODE=clip node test/route_video.mjs <폴더>`(계산 걸음 4개마다 찍은 1배속 64.6초. 단계 끝의 접촉이 계산 시험과 같다). 영상은 약 7초 간격으로 9장을 봤다.
- **화살표와 다른 곳**: 턱 C에서 턱 D로 바로 가지 못했다(오른손이 16cm 모자라고, 옆으로 가면 어깨·머리가 턱 B 밑에 걸린다). 턱 B로 내려와 오른쪽으로 간 뒤 뛰어 잡았다.
- **한 번에 찾은 입력이 아니다.** 고쳐 가며 찾았다: 넓은 발판에 서는 자리(벽에서 28cm), 한 손을 턱 C에 둔 채 다른 손(턱 B)을 옮기면 떨어짐 → 두 손을 먼저 턱 C로, 턱 C → 턱 D 직행 불가 → 턱 B 경유, 턱 E에서 손 순서(엇갈려 "팔이 턱에 걸려").
- 자작 동작에서는 5단계에서 왼손을 놓치고 6단계의 점프가 46cm 모자라 실패한다(자작 동작은 비교용).

## 2. 가 보다가 찾아 고친 결함

마우스로 겨눈 곳을 보느라 돌린 고개가 잡은 팔에 들어가 손을 놓치고 떨어졌다(`자세_보조_p3d-0.12.0.md` 11.2절). 시험과 영상은 겨눈 곳을 넘기지 않아 한 번도 지나지 않은 길이었다. p3d-0.12.4에서 고쳤다.

## 3. 단계별 여유 (`MODE=clip node test/route_tolerance.mjs`)

손·발 명령 하나마다 입력을 **한 가지씩만** 흔들어, 그 명령의 구간이 끝난 때 그 손발이 기준과 같은 턱을 실제로 잡았는가(뛰는 단계는 단계 끝)를 봤다. 298가지 가운데 241가지가 같다.

| 흔든 것 | 같음 | |
|---|---|---|
| 겨눈 자리를 턱을 따라 옆으로 ±8cm | 51/52 | |
| 〃 ±15cm | 44/52 | 다른 손·턱의 끝과 부딪히는 자리 |
| 겨눈 자리 = 턱의 앞면 | 24/24 | |
| **겨눈 자리 = 턱 위쪽 벽면(5cm 위)** | **8/24** | "잡을 수 있는 턱이 아님" |
| **겨눈 자리 = 턱 아래쪽 벽면(10cm 아래)** | **0/24** | "잡을 수 있는 턱이 아님" |
| 보내는 시각 ±0.25초·±0.5초(뛰지 않는 단계) | 94/96 | |
| **발판에서 뛰어 턱 C: 점프 뒤 0.10·0.15·0.20·0.30초** | **0/4** | 점프 전 0.10초 ~ 뒤 0.05초만 잡음 |
| 매달려 뛰어 턱 D: −0.10 ~ +0.30초 | 7/7 | |
| W·D 누르는 길이 0.6배·1.5배 | 10/12 | 턱 B로 가기 전의 W(1.25초)는 짧아도 길어도 실패 |

- **조준**: 지금 판정은 "겨눈 점에서 3차원 거리 14cm(`CL.SNAP`) 안에 턱 모서리"다. 턱이 벽에서 14~16cm 튀어나와 있어, 벽면을 누르면 깊이만으로 한계에 닿는다 — 턱 바로 위아래의 벽을 누르면 대부분 거부된다. 턱의 겉(앞면·윗면·밑면)을 누를 때만 30cm까지 너그럽다. 사용자가 말한 "완벽한 포인트"가 이것으로 보인다.
- **뛰어 잡기**: 발판에서 뛰는 턱 C는 점프와 거의 동시에 눌러야 한다(창 약 0.15초). 늦으면 낮은 턱(턱 F)을 잡고 있던 손이 "몸이 손을 지나 올라가 놓음"으로 풀리고 손을 다시 보낼 때는 정점이 지났다.
- **몸 입력**: 대부분 길이에 너그럽지만, 닿는 거리가 아슬아슬한 단계(5)는 W의 길이에 따라 갈린다.

### 이 측정이 보지 못하는 것

- 카메라 너머로 마우스로 겨누는 것(화면에서 턱은 가는 줄이다), 어느 손을 어떤 순서로 보낼지 모르는 것, 여러 입력이 함께 어긋나는 것, 실패한 뒤의 복구.
- 그래서 "241/298"은 **순서를 다 아는 상태에서 하나만 틀렸을 때**의 값이다. 사람이 느끼는 난이도가 아니다. 사용자는 이 벽을 가지 못했다.

## 4. "대충 해도 되게" 하는 후보 (개발 쪽 의견. 조작 컨셉은 그대로, 모두 옵션으로 넣어 같은 측정으로 전후를 견준다)

1. **조준을 너그럽게**: 누른 화면 자리에서 가장 가까운 잡을 수 있는 턱을 고른다(깊이를 빼고 잰 거리, 20~30cm 안). 누르기 전에 잡힐 턱을 표시한다. 물리는 그대로다.
2. **먼저 누르고 뛰어도 잡게**: 닿지 않는 턱으로 보낸 손이 0.3초 뒤 거부되는 대신, 뛰면 닿는 높이면 손을 든 채 1~2초 기다렸다가 닿는 걸음에 잡는다. 타이밍이 0.15초에서 초 단위가 된다.
3. **조금 모자라면 몸이 알아서 맞추게**: "몇 cm 모자람"이면 지금 디딘 발·잡은 손으로 갈 수 있는 만큼 몸이 스스로 일어서거나 옮긴다(W·D를 얼마나 누를지 맞추지 않아도 된다). 닿는 거리가 실제로 느는 변경이다 — 앞서 GPT가 "기본 방향이 아니다"라고 한 것(p3d-0.9.0)과 닿으므로 사용자 결정이 필요하다.

그 밖: 손을 엇갈려 보내면 자동으로 반대 손으로 바꾸기(손 조작 2가 이미 추천 손을 쓴다), 한 손을 옮길 때 떨어질 것이 보이면 미리 알리기.
