# GPT 전달 — p3d-0.11.0 ~ p3d-0.15.0 (전신 자세 풀이 → 쉬운 조작 → 클라이밍장 → 누르기·기운 벽)

마지막으로 전달한 것은 **p3d-0.10.4**(`GPT_요청_p3d-0.10.4.md`)다. 그 뒤 열한 판을 한꺼번에 전달한다. 그사이 GPT 요청으로 한 CMU 동작 분석(`CMU_동작_분석.md`)도 함께 넣었다.
상태: **기술 반영, 시각/사람 확인 대기.** 이 문서의 수치는 따로 적지 않으면 스크립트 입력(사람 손 아님)이다.

## 0. 먼저 알아 둘 것

- **역할**: GPT = 그래픽·UI·기획, Claude = 개발. 아래의 화면·문구·코스 모양·난이도 이름은 모두 개발이 임시로 넣은 것이다.
- **사용자가 직접 해 본 범위**: 0.11.0 ~ 0.11.10(영상과 의견을 여러 번 받음), 0.12.0(얼굴이 벽에 붙는다는 지적), 0.12.4의 옛 연습용 벽(사용자는 경로를 끝까지 가지 못했다). **0.13.0 ~ 0.15.0(쉬운 조작·클라이밍장·누르기·기운 벽)은 사용자가 아직 해 보지 못했다.** 이 구간의 근거는 시험 봇과 계산 시험뿐이다.
- **그사이 사용자가 정한 원칙**(2026-11-25, 옛 연습용 벽을 해 보고): "기본 동작은 대충 해도 되어야 한다. 어려움은 조작이 아니라 맵에 둔다. 맵은 쉬운데 그걸 하려는 컨트롤이 너무 세밀하고 너무 완벽한 포인트를 집어야 한다. 이대로면 금방 질린다." 조작 컨셉(WASD = 몸, 마우스 = 손, Shift = 발)은 유지.
- **캡처 동작으로만 진행**(사용자 결정, 0.11.4). 묶음의 실행 파일은 공개 가능한 자작 동작 빌드(`climb3d.html`)다 — 캡처 빌드와 그 화면은 넣지 않는다. 수치는 캡처 동작으로 잰 것이다.

## 4. 요청 — 기획

1. **쉬운 조작의 방향과 범위**: "기본 동작은 대충, 어려움은 맵에"를 어디까지 풀지. 지금 넣은 셋(조준 맞춤 26cm, 예약 2초, 자동 몸 맞추기 30cm·1.2초)의 값은 실험값이다. 특히 ③은 "손을 닿게 하려고 몸을 자동으로 옮기지 않는다"는 앞선 방향(0.9.0)과 닿는다 — 기본으로 둘지.
2. **누르기**(낮은 손 위로 몸 올리기)를 기본 동작으로 둘지, 그리고 그다음 지지 동작의 순서: 맨틀(손으로 눌러 올라서기) / 높은 발 올리기(40cm 넘게) / 허리 돌리기 / 교차의 안·밖 고르기 / 몸통 힘 한계(`몸통_근육_설계안.md`).
3. **코스 설계 기준**: 지금 코스의 간격(쉬움 26~28cm, 어려움 36~42cm)은 "이 몸이 오를 수 있는 한계"에 맞춘 것이지 실제 암장 기준이 아니다. 난이도를 무엇으로 만들지(손 사이 거리 / 홀드 크기 / 방향 / 뛰어 잡기 / 기운 정도) — 사용자 원칙대로면 어려움은 맵에서 나와야 한다.
4. **코스 규칙**: 지금은 색이 규칙일 뿐 다른 색 홀드도 잡힌다(실제 암장처럼). 코스를 고르면 그 색만 잡히게 할지, 완등 판정(두 손이 완등 홀드를 0.5초)과 시작 규칙, 기록(시간·시도 수)을 둘지.
5. **발 보조가 손 홀드에도 발을 올린다**(지금 잡고 있지 않은 홀드). "벽의 턱은 발판이 아니다"와 어긋나 보일 수 있다 — 클라이밍장에서는 허용할지.
6. **벽을 어디서 만들지**: 사용자가 외부 제작 도구에서 벽을 만드는 것을 물었다. 개발 쪽 의견: 지금 막히는 곳은 도구가 아니라 엔진(상자만 안다)이다. 도구로 옮기려면 엔진이 기운 면·모서리를 직접 다루게 넓히는 것이 먼저다. 그 일을 지금 할지, 캐릭터 동작이 선 뒤에 할지.
7. 리드 벽(12m)에 줄(로프·확보)을 둘지, 떨어짐을 어떻게 다룰지(지금은 그냥 바닥에 선다).

## 5. 요청 — 그래픽

1. **클라이밍장의 모양**: 벽 색·색 띠·매트·홀드 색·코스 이름표·시작/완등 테이프가 모두 임시다. 묶음의 그림 3장(전경·오버행·슬랩)과 사용자가 보낸 실제 암장 사진의 느낌(회색 벽 + 큰 빨강·파랑·노랑 면, 빼곡한 홀드, 큰 볼륨, 가파른 오버행)을 기준으로 시안.
2. **홀드 모양**: 지금은 모두 납작한 상자(폭 10~50cm, 깊이 5~14cm)다. 물리는 "윗모서리를 잡는다"뿐이라 그림은 그 모서리를 가진 어떤 모양이어도 된다 — 홀드 종류별 시안(큰 홀드·작은 홀드·발 홀드·볼륨).
3. **누르는 손의 모양**: 지금은 손이 잡을 때 모양 그대로 몸만 위로 올라간다(손목이 뒤로 꺾여 보일 수 있다 — 개발 쪽에서 그림으로 확인하지 못했다). 손바닥을 윗면에 올려 누르는 손, 팔꿈치 방향의 시안.
4. 오버행에 매달린 자세·슬랩에 선 자세의 참고(몸이 지금은 세로 벽을 기준으로 선다).
5. 앞 판에서 남은 것: 끝 옆면을 잡은 손 모양(0.10.4 요청 1), 뻗는 동안의 팔꿈치(뒤로 12~20cm), 손가락 끝이 턱에서 22mm 뜨는 장면.

## 6. 요청 — UI

1. **쉬운 조작의 표시**: 조준 맞춤으로 잡힐 턱의 표시, 예약 중 표시("◌ 예약: 닿으면 잡음 — 다가가거나 뛰기"), 자동 몸 맞추기 표시("몸을 옮겨 닿는 중") — 문구와 모양 모두 임시.
2. **미리보기가 틀릴 때가 있다**: "닿지 않음"이라 보이는데 눌러 보면 잡히는 경우가 336가지 가운데 130이다(손을 놓은 뒤 몸이 옮겨 가는 몫을 세지 못한다). 미리보기를 어떻게 보일지("닿음 / 뻗어 보면 될 수도 / 안 닿음" 같은 세 단계 등).
3. **코스 표시**: 지금 코스·완등 표시(화면 왼쪽 위 한 줄), T로 코스 옮기기 — 코스 고르기 화면, 완등 연출, 기록 표시.
4. 옵션이 일곱 개(F·U·Y·L·P·H·J)로 늘었다. 플레이어에게 보일 것과 숨길 것, 묶을 것(예: "쉬운 조작" 하나로).
5. 거부 문구 가운데 새것·임시: "누르는 방향이 턱에서 벗어남", "닿지 않음(점프 정점이 지남 · …cm 모자람)", "잡던 자리로 돌아가 기다림".
