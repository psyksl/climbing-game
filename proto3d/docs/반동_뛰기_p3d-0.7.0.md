# p3d-0.7.0: 벽에서 반동(흔들기)과 뛰기, 공중에서 다시 잡기 (2026-11-20)

- 근거: GPT의 p3d-0.5.0 검토 P3의 앞부분("반동/벽 도약·재잡기"), 사용자 의견 ①(아케이드성이 없다). 사용자가 "작업을 이어서 진행하자"고 했고, 다음 순서는 개발 쪽 권고(뛰기·반동 먼저)대로 정했습니다. **GPT의 답(뛰기의 입력·손을 저절로 놓는지)은 아직 받지 않았습니다** → 아래 입력은 임시입니다.
- 모든 수치는 **스크립트 입력의 자동 측정**입니다. 사람이 해 본 결과는 없습니다. 숫자는 임시값입니다.
- **이번 판까지 한 것: 반동·벽에서 뛰기·공중 재잡기의 물리와 점검.** 30~60초 코스(시작·도착·두 경로)와 턱 위로 올라서기(맨틀)는 **아직 없습니다.**

## 1. 조작 (임시)

| 문맥 | 입력 | 동작 |
|---|---|---|
| 벽(손으로만 매달림) | A / D | 엉덩이를 흔들어 반동 만들기. 흔들리는 쪽과 같은 때에 누르면 커지고 반대로 누르면 줄어든다(화면에서 보이는 쪽) |
| 벽(발로 디딘 상태) | A / D | 전처럼 몸을 옆으로 옮기기 |
| 벽 | Space | 뛰기. 누르는 순간 0.2초 동안 밀고(모으기 없음, 지상 점프와 같다), 일찍 떼면 그때 밀기가 끝난다 |
| 벽 | Space + A/D | 그쪽 위로. **흔들어 그쪽으로 가는 중에 뛰면** 흔들던 속도가 그대로 이어진다 |
| 벽 | Space + W / S | 더 위로 / 벽을 차고 뒤로 |
| 공중 | 좌클릭 / 우클릭 | 겨눈 턱으로 왼손 / 오른손(지상에서 뛰어 떠 있는 동안에도 우클릭은 누르는 순간. 그동안 시점 돌리기는 쉰다) |

- 뛰어도 **손을 저절로 놓지 않습니다**(GPT 질문 3번의 임시 답). 잡을 턱을 클릭하면 그 손이 놓이고 뻗습니다. 몸이 손을 지나 위로 올라가면(팔이 다 접힘) 그 손은 저절로 놓입니다.

## 2. 물리 (임시값)

| 값 | 내용 |
|---|---|
| 흔들기 `SWING_A` 1.3m/s² | 손으로만 매달렸을 때 A/D가 벽과 나란한 쪽으로 주는 힘. **실제로는 엉덩이·다리를 차서 흔드는 것을 질점 몸에 옮긴 근사**입니다(질점에는 안에서 미는 힘이 없음). 팔 길이 구속이 진자 운동으로 바꿉니다 |
| 매달린 흔들림의 감쇠 `HANG_DAMP` 0.12/초 | 전에는 접촉이 있으면 0.6/초로 줄여 흔들림이 바로 죽었다 |
| 매달려 흔들 때 | 수평 기준 자리를 몸에 맞춰 흔들림을 붙잡지 않음. 몸 전체가 손을 축으로 기울고(최대 34°), 팔꿈치의 기본 방향이 몸통을 따라 돈다(꼿꼿한 몸이 옆으로만 밀리면 팔이 머리를 지나가 손을 놓쳤다) |
| 뛰기 `PUSH_A` 17m/s², `PUSH_T` 0.2초 | 미는 쪽으로 원하는 가속. 실제로 나는 힘은 **손발이 낼 수 있는 만큼**(같은 힘 나누기): 발판을 디딘 다리는 크게 밀고, 매달렸으면 팔로 당기는 만큼만, 팔은 벽 쪽 옆으로는 거의 못 민다 |
| 뛰는 동안 팔 힘 `ARM_BURST` 0.85배 | 0.2초 동안 한 팔이 순간적으로 낼 수 있는 당기는 힘(평소 버티는 힘은 0.65배) |
| 저절로 놓임 `FOLD` 24cm | 팔이 다 접힌 채(어깨~손목 24cm 안) 위로 가는 중이면 그 손은 놓인다(누르기로 바뀌는 맨틀은 없음) |
| 턱 D·E | 확인용으로 새로 놓음. 턱 D = 턱 B의 26cm 위·오른쪽, 턱 E = 턱 B의 오른쪽 0.9m·42cm 아래 |

## 4. 하지 않은 것 · 숨기지 않는 것

1. **코스가 없습니다**(GPT P3의 시작·도착·두 경로·빠른 재시작). 다음 판의 일입니다. 한 화면 크기 벽에서 두 경로를 만들려면 턱 배치를 사람이 해 보며 맞춰야 해서, 먼저 움직임을 넣고 점검했습니다.
2. **맨틀(턱 위로 올라서기)이 없습니다.** 손으로 누르는 동작이 없어 몸이 손 위로 가면 손이 놓입니다.
3. 흔들기는 질점 몸에 옆으로 미는 힘을 준 근사입니다. 다리가 곧은 막대처럼 함께 흔들립니다(자세 문제는 그대로).
4. 매달린 채 옆으로 뛰면 팔이 벽 쪽 옆으로는 거의 밀지 못해 위로만 뜁니다(턱 E에 못 닿음). 사실에 가깝다고 보지만, 게임으로 너무 답답한지는 사람이 봐야 합니다.
5. 반동 진폭이 30cm 언저리에서 더 커지지 않습니다(감쇠·몸 기울기 한계). 더 크게 흔들어야 하는 거리는 지금 만들 수 없습니다.
6. 손 조작 2번(누르는 동안 뻗기)과 발 보조는 이번 점검에서 켜지 않았습니다(반동·뛰기 점검은 1번 + 보조 끔).

## 5. GPT에 요청하는 것 (역할별)

**기획**
1. 벽에서 뛰기의 입력(임시: Space + 방향, 손은 저절로 놓지 않음)을 유지할지.
2. 흔들기를 A/D로 하는 것(같은 키가 발을 디뎠을 때는 몸 옮기기)이 헷갈리지 않을지.
3. 다음 판의 코스: 시작·도착·두 경로(발로 오르기 / 반동·뛰기). 턱 위치와 높이는 개발 쪽이 맞추되, "어떤 기술을 써야 하는 구간"을 정해 주시면 그에 맞춰 배치합니다.
4. 맨틀을 코스 전에 넣을지(도착을 "맨 위 턱을 잡음"으로 할지 "윗면에 올라섬"으로 할지).

**UI**
5. 흔들림의 크기·방향을 보여 줄지(2D에서 하던 이동 방향 화살표). "지금 뛰면 좋은 때"를 알려 줄지(개발 쪽 의견: 화살표만 보이고 때는 스스로 익히게).
6. 뛰는 중의 표시(밀기 0.2초).

**그래픽**
7. 흔들 때 다리를 굽혀 차는 모양(지금은 곧은 몸이 통째로 흔들림).
