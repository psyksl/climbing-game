# p3d-0.11.0 — 전신 자세 풀이(첫 판)

사용자 결정(2026-11-23): 규칙 덧대기를 멈추고 전신을 한 번에 푸는 방식을 넣어 본다. **판단은 사람 플레이.** 상태: 기술 반영, 시각/사람 확인 대기. 숫자는 스크립트 입력(사람 손 아님).

## 무엇이 바뀌었나

- `src/fbik.js`: 붙은 손발·가는 손발·무게중심(물리가 준 자리)·지형을 주면 골반(자리·회전)·척추·가슴·빗장뼈 11개 값을 **값(비용) 하나를 줄여** 함께 푼다. 0.10.x의 규칙들(윗몸 기울기·비틀기·골반 층·엉덩이 빼기·어깨 올림·머리 위 턱 피하기)을 대신한다.
  - 값에 든 것: 무게중심은 그대로(골반이 가면 윗몸이 반대로) · 팔다리가 늘어나거나 다 접히지 않게 · 잡은 팔은 편한 길이(85%) 쪽으로 · 잡은 손이 미끄러지는 방향·등 뒤로 가지 않게 · 하중 받는 발 위로 고관절 · 무릎·넓적다리·몸통·머리가 지형에 닿지 않게 · 몸통 축은 받치는 쪽(매달리면 손 쪽) · 척추가 꺾이는 한계 · 뻗는 손 쪽으로 어깨가 다가감.
  - 계산 걸음에서만 풀고(감쇠 최소제곱 한 걸음 + 임계 감쇠 스프링), `torso()`를 거쳐 물리와 그림이 같은 값을 쓴다. 손발 접촉·판정·힘은 그대로다. 팔꿈치·무릎 방향 고르기도 0.10.4 그대로(다음 판 후보).
- 발이 받치지 않는 매달림에서 위·아래 입력이 없으면 팔이 거의 펴질 때까지 몸이 가라앉는다(**임시 — 조작에 닿는다**: 당겨 올라간 채 다른 손을 보내려면 W를 누르고 있어야 한다. `S.opt.hangSink = false`로 끔).
- 화면: 기본 = 전신 자세 풀이. **O 키**로 옛 규칙(0.10.4)과 바로 바꾼다(주소 `?posture=rule`). 시험(sim)의 기본은 옛 규칙 그대로(`POSTURE=fb`로 새 방식).

## 잰 것

|---|---|---|
| 벽 시험(옛 규칙 기준으로 만든 83개) | 76 / 7(0.10.4와 항목별 같음) | 68 / 15 |

| 계산 시간(걸음당) | 0.24~0.66ms | 0.38~0.86ms |

- 벽 시험에서 새로 실패한 10개는 대부분 **닿는 거리·높이가 달라져서**다(옛 규칙의 수치에 맞춘 장면): 닿지 않아야 할 옆 발판을 디딤(골반이 발 쪽으로 가서 다리가 더 닿는다), h3의 "7cm 모자람"이 잡힘(어깨가 목표 쪽으로 간다), 두 팔 당김 높이 15cm(기준 20cm), 뛰어 잡기·흔들기의 때. 결함으로 보는 것: 놓인 손이 벽에 14걸음 든 경우 3/18.
- 닿는 거리가 달라진 것은 이 방식의 성질이다(몸이 손발 쪽으로 간다). 얼마가 맞는지는 플레이로 정한다 — 옛 수치를 정답으로 두지 않았고, 새 방식에 맞춰 장면을 고치지도 않았다.

## 눈으로 본 것(개발 쪽, 정지 장면만 — 판정 아님)

- 매달림: 옛 = 팔을 굽힌 채 멈춤, 새 = 팔을 펴고 가라앉음. 당겨 오르기는 좌우가 같다(가슴이 까닭 없이 틀어지던 것은 고침).
- 발판에 선 자세(h1): 새 = 윗몸이 벽에서 뒤로 눕고 엉덩이가 벽 쪽(팔이 덜 접힌다), 골반이 디딘 발 쪽으로 돈다. 옛 = 꼿꼿이 서고 팔꿈치가 손 높이로 벌어진다.
- 아직 어색한 것: 엇갈려 디딘 다리에서 골반이 30°쯤 크게 돈다, 고개가 많이 젖혀진다, 팔꿈치 모양은 옛 방식 그대로.

## 하지 않은 것

팔꿈치·무릎 방향을 풀이에 넣기, 놓인 팔다리의 균형 몫, 브라우저 입력 시험 다시 돌리기(기본이 새 방식으로 바뀜 — 옛 시험은 `?posture=rule`로 봐야 한다), 다른 벽 장면을 새 방식에서 통과시키기, 무게 값 맞추기(전부 실험값), Blender·Tripo.

## 사용자에게 부탁

같은 구간을 **O 키로 바꿔 가며** 해 보고: ① 새 방식이 더 사람 같은가 ② 매달리면 가라앉는 것이 괜찮은가 ③ 가장 거슬리는 한 가지.
