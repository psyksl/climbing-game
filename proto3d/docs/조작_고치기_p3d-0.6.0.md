## 2. 지금의 조작 (임시 배치. 모두 다시 정할 수 있음)

| 문맥 | 입력 | 동작 |
|---|---|---|
| 지상 | W A S D · L Shift · C · Space | 이동 · 달리기 · 웅크리기 · 점프(오래 누르면 높이) |
| 지상 | 우클릭을 누른 채 끌기 | 시점 돌리기 |
| 지상 | 좌클릭 / 우클릭 짧게 | 겨눈 턱에 왼손 / 오른손 |
| 지상 | L Shift + 클릭 | 손 대신 발(발부터 올리기) |
| 벽 | 좌클릭 / 우클릭 | 왼손 / 오른손(누르는 순간) |
| 벽 | Q / E | 왼손 / 오른손 놓기 |
| 벽 | L Shift + 클릭, Q / E | 손 대신 발 |
| 벽 | W S A D | 몸 위 · 아래 · 왼쪽 · 오른쪽(**화면에서 보이는 쪽**) |
| 언제나 | V | 시점 보기 모드(조작 멈춤). 그 안에서 우클릭 끌기 = 시점 |
| 언제나 | 휠 | 가까이·멀리 |
| 언제나 | H | 손 조작 방식(1 눌러 보내기 ↔ 2 누르는 동안 뻗기) |
| 언제나 | F | 발 보조 켬·끔 |
| 언제나 | T · R · K | 작은 벽 앞에서 시작 · 처음 자리로 · 조작표 모두 보기 |

- 개발·시험용 키(진단 I, 뼈대 B, 느리게 N, 모션 M, 동작 보기 G …)는 조작표에서 접어 두었습니다(K로 폄).
- 지상의 우클릭은 "끌기 = 시점"과 "짧게 누르기 = 오른손"을 나눠 씁니다(6픽셀·0.35초 기준). **개발 쪽 의견**: 지상에서 오른손이 뗄 때 나가 왼손보다 한 박자 늦습니다. 불편하면 지상의 오른손을 다른 입력으로 옮기는 것이 낫습니다.

## 3. GPT의 P0 세 가지

| P0 | 한 일 | 측정 |
|---|---|---|
| 1 잘못된 목표를 누르면 잡고 있던 손까지 풀림 | 거부(`deny`)는 새 명령만 받아들이지 않고 지금의 접촉은 그대로 둡니다. 옮기기를 실제로 시작한 뒤의 실패(`reject`)와 직접 놓기는 따로 기록합니다. 발도 같습니다 | 잡고 있는 손으로 턱이 아닌 곳 → 거부, 계속 잡음 / 잡고 있는 자리를 다시 → 거부 / 빈손으로 → 거부, 다른 손 그대로 / 옮기기 시작한 뒤 닿지 못함 → 놓음 → 실패 → 떨어짐(전 자리로 되돌아가 붙지 않음) / 직접 놓기 → 놓음 / 디딘 발로 닿지 않는 곳 → 거부, 계속 디딤. 실제 클릭으로도 확인 |
| 2 몸 좌우의 기준이 설명과 다름 | 화면에서 보이는 쪽으로 통일했습니다. 화면 쪽이 시점과 몸의 방향으로 부호(`cxSign`)를 정해 넘깁니다. 시점이 옆(벽과 나란한 쪽)이라 불안정할 때는 마지막 부호를 그대로 씁니다 | 뒤에서 볼 때 "오른쪽" = +12.0cm, 반대편에서 볼 때 −12.0cm. 시점을 반대편으로 돌린 것만으로 잡은 손·몸은 움직이지 않음 |
| 3 뛰어 잡기의 지연에 따른 구멍 | 원인: 손이 0.22~0.6초의 정해진 시간표로만 가고, 그 시간이 끝난 뒤에야 닿았는지 봤습니다. 손이 가는 도중에 몸이 닿는 범위를 지나가면 못 잡았습니다. 고친 것: 손은 몸과 함께 가면서 목표를 향해 실제 속도(초속 3.2m까지)로 다가가고, **닿을 수 있게 된 걸음에 잡습니다.** 더 갈 수 없게 된 뒤로 0.3초만 더 뻗고 있습니다 | 점프를 누른 뒤 0~0.7초를 2걸음 간격(43가지)으로: 0~0.233초에 보내면 두 손 모두 잡고, 그 뒤로는 못 잡음. **구간 안의 실패 0개**(캡처 모션은 0~0.267초). 이 장면의 계산 결과이며 사람의 성공률이 아닙니다 |

- GPT가 잰 p3d-0.5.0의 구멍(0~0.033초 잡힘 / 0.05~0.15초 실패 / 0.167~0.417초 잡힘)과 견주면, 점프 자체가 바뀌어(즉시 점프) 시각의 기준이 다릅니다. "구간이 하나로 이어져 있다"만 같은 뜻으로 견줄 수 있습니다.

## 4. 비교용 선택 두 가지 (GPT의 P1·P2에 해당. 사람이 견줘 보고 정할 것)

같은 물리·같은 지형 위에서 **입력이 의도로 바뀌는 층만** 다릅니다. 하나씩 따로 켜고 끌 수 있습니다.

### 손 조작 방식 (H)

| | 1 · 눌러 보내기(기본, 기존 방식) | 2 · 누르는 동안 뻗기(GPT 후보) |
|---|---|---|
| 누르는 순간 | 겨눈 턱으로 손을 보냄. 갈 수 없는 목표면 거부(잡은 손 유지) | 그 손을 놓고(의도적인 놓기) 겨눈 쪽으로 뻗기 시작 |
| 누르는 동안 | — | 마우스를 따라 손이 감(턱 가까이면 그 턱의 잡을 자리로) |
| 뗄 때 | — | 턱이면 잡고, 아니면 헛손질 |
| 지상의 오른손 | 우클릭 짧게 | 같음(지상의 우클릭 끌기는 시점이라 뻗기를 쓸 수 없음) |

### 발 보조 (F) — 간편 조작 / 정밀 조작

- **켬(기본)**: 손으로 잡고 있는 동안, 놓여 있는 발을 가까운 발판 윗면으로 보냅니다. 직접 보낼 때와 **같은 명령·같은 이동·같은 판정**을 거칩니다. 한 번에 한 발.
- 하지 않는 것: 벽면에 발 붙이기, 다음 경로 미리 찾기, 순간이동, 손이 없을 때 구하기, 디디고 있는 발을 더 나은 자리로 자꾸 옮기기, 손으로 잡은 턱에 발 올리기.
- 측정(같은 입력, 턱 A를 두 손으로 잡고 W 2.5초): 켬 = 한 발이 낮은 발판을 디뎌 몸무게의 0.76배를 받고 손은 합 0.28배, 몸 +34cm / 끔 = 두 발이 떠 있고 손이 합 1.07배, 몸 +21cm.
- 발판이 없는 곳(턱 B 아래)에서는 켜도 발을 붙이지 않고 매달린 채 둡니다. 손을 놓고 떨어질 때 다시 붙여 구하지 않습니다.
- **직접 뗀 발(Shift + Q/E)은 1.5초 동안 보조가 다시 보내지 않습니다.** 그 뒤에는 다시 보냅니다 — "의도적인 발 떼기"를 오래 유지하려면 지금은 보조를 꺼야 합니다(한계).

## 7. 하지 않은 것 · 숨기지 않는 것

1. **재미를 만드는 것**(GPT의 P3): 벽에서 뛰기, 반동을 키우는 조작, 턱 위로 올라서기(맨틀), 시작·도착이 있는 30~60초 코스. 다음 판의 일입니다.
2. **자세의 자연스러움**(의견 8·9): 벽에서의 몸통은 곧은 막대이고 기울기·어깨 올림은 규칙입니다. 떨어질 때 몸이 곧은 채 떨어집니다. 고치려면 몸통 구조를 올려야 합니다.
3. 발 보조는 "뗀 발을 가까운 윗면으로"까지입니다. 벽면에 발을 대고 버티는 것, 손을 옮기는 동안 발을 미리 옮기는 것은 하지 않습니다.
4. 14cm 발판에 서는 것은 무게중심이 그 발 위에 있을 때입니다. 옆으로 27cm 떨어진 채 손을 놓으면 0.08초에 균형을 잃고 떨어집니다. **1cm처럼 아주 좁은 턱은 시험하지 않았습니다**(지금 벽에서 가장 좁은 발판이 14cm). 실제 클라이밍처럼 발끝·손가락 끝으로 버티는 것은 턱의 종류(깊이·기울기)와 악력을 다루는 다음 일입니다.
5. 손 조작 2번에서 손은 벽·턱을 뚫지 않게 막는 처리가 없습니다(잡는 순간의 팔 자세만 확인). 허공을 휘젓는 동안 손이 벽 속으로 들어갈 수 있습니다.
6. 화면을 멈춰 두는 동안 몸이 90cm 넘게 벗어나면 그만큼만 따라갑니다. 이 값이 맞는지는 사람이 봐야 합니다.
7. 진단 숫자(하중·오차·fps)는 I 키로만 보입니다. 이름표가 겹치면 좌우로 벌리지만 연결선은 없습니다.

## 8. GPT에 요청하는 것 (역할별)

**기획**
1. 손 조작 1·2번과 발 보조 켬·끔의 사람 비교 결과를 보고 기본값 정하기(지금 기본: 1번 + 보조 켬).
2. 지상의 오른손 입력(우클릭 짧게). 지상에서 우클릭 끌기가 시점이 되면서 생긴 타협입니다.
3. 시점 보기 모드를 V로 켜고 끄는 방식(누르고 있는 동안만으로 할지).
4. 즉시 점프의 높이 조절(바로 떼면 0.19m, 끝까지 0.48m)과 뛰어 잡기의 구간(0~0.23초)이 맞는 난이도인지.
5. 벽에서 뛰기의 입력: Space 하나로 할지, 뛸 때 손을 저절로 놓을지(다음 판의 첫 일).

**UI**
6. 겨눈 자리 표시(지금은 턱 위의 작은 점 하나), 시점 보기 모드 표시, "손 조작 1·2 / 발 보조" 표시 줄.
7. 미리보기 문구("조금 더 가까이" 등)와 이름표를 벌린 뒤의 연결선.

**그래픽**
8. (전과 같음) 턱을 잡은 손, 벽에 댄 발, 떨어지는 몸의 모양.

**개발 쪽 의견**
- 의견 8·9(어색한 관절, 넘어지는 모션)는 지금 구조에 규칙을 덧대서는 한계가 뚜렷합니다. 다음 판에서 "벽에서 뛰기·반동"을 먼저 넣어 재미를 확인할지, 몸통 구조(강체 몸통·골반 분리)를 먼저 올릴지 정해 주시면 좋겠습니다. 개발 쪽은 **뛰기·반동을 먼저** 권합니다(재미가 없으면 자세를 다듬어도 소용이 없고, 뛰기에서 몸통 회전이 얼마나 필요한지가 드러납니다).
