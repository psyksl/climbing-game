## p3d-0.2.0: 캡처 동작 적용 (2026-11-19, 사용자가 준 Mixamo 동작) — 아래 가운데 "자작 모션이 맡는다"와 실패 3개는 p3d-0.3.0에서 바뀌었습니다

### 어떻게 옮겼나 (`tools/mixamo_convert.mjs`)
- 뼈마다 "원본의 쉬는 자세에서 지금까지 돈 회전"을 우리 뼈에 줍니다(뼈 65개 → 21개. 손가락은 없음). 쉬는 자세가 다른 만큼(원본 = 팔을 옆으로, 우리 = 팔을 내림)은 뼈마다 한 번 맞춥니다.
- 다리는 한 번 더 맞춥니다: 발목 자리 = 고관절 기준 원본 발목 자리 × 다리 길이 비(0.945), 엉덩이 높이 = 원본 발목이 쉬는 높이일 때 우리 발목도 쉬는 높이. 방향만 옮겼을 때는 디딘 발이 1~3cm 뜨거나 묻혔습니다.
- 걷기·달리기는 한 주기의 평균 이동을 빼서 "제자리 자세 + 보폭"으로 나눕니다. 몸을 옮기는 것은 전처럼 `controller.js`입니다.
- 발이 닿는 구간은 원본에서 발목·발볼이 낮고 거의 서 있을 때로 정해 함께 적어 둡니다. 왼발이 닿는 순간을 위상 0으로 돌려, 걷기와 달리기를 같은 위상으로 섞을 수 있게 합니다.

- 걸음 위상은 실제 간 거리 / 보폭으로만 나아갑니다(자작 모션과 같은 규칙). 속도에 따라 서 있기 ↔ 걷기 ↔ 달리기를 섞습니다.

## W1.1 (p3d-0.1.1): GPT 검토 반영 — 계산·그리기 분리, 지지 구간 측정, 걸음·상체, 카메라 벽

### 1. 화면 빠르기(FPS)에 따라 자세가 달라지던 문제
- 원인: 실제 실행은 자세 계산(`applyPose`)을 **화면을 그릴 때마다** 했고, 시험 함수는 **계산 걸음마다** 했습니다. 이 함수가 다음 계산이 읽는 값(다리가 닿는지, 발목 자리, 발끝/뒤꿈치 축, 엉덩이를 낮출 몫)을 바꾸고 있어서, 같은 입력에서도 FPS에 따라 무릎·발 상태가 달라졌습니다.
- 고친 것: 고정 간격 계산 한 걸음 = 이동 → 상태 → **자세·접촉 확정**(`src/sim.js`의 `step`). 실제 화면 루프(`frameCore`)와 시험이 모두 이것만 부릅니다. 그리기는 확정된 뼈 자세를 보여 주기만 하고 계산 상태를 바꾸지 않습니다. 자세 계산은 한 걸음에 한 번입니다(두 번 하지 않음).
- 대조(같은 계산 시각의 뼈 자리):

  | | 고치기 전 p3d-0.1.0 (GPT 재현 도구 `fps_probe.cjs`) | 고친 뒤 p3d-0.1.1 (`test/fps_check.js`, 실제 화면 루프) |
  |---|---|---|
  | 60Hz(fps) | 무릎 최대 5.08cm 다름 | 0 (뼈·몸·디딘 자리·발 상태 모두 같음) |
  | 30Hz(fps) | 무릎 최대 7.64cm 다름, 발 상태가 다른 시각 1 | 0 |
  | 144fps | — | 0 |
  | 7~45ms로 들쭉날쭉한 간격 | — | 0 |

  `fps_check.js`는 빌드의 실제 프레임 함수(계산 진행 + WebGL 그리기)를 프레임 간격 목록대로 돌립니다. GPU 성능 측정이 아닙니다.
- 높은 화면 빠르기(예: 144fps)에서는 계산(120Hz)보다 그림이 잦아 같은 자세를 두 번 그리는 프레임이 생깁니다. 보간은 아직 넣지 않았습니다(넣더라도 그리기 쪽에서만, 계산 상태를 바꾸지 않게).

### 2. 발 미끄러짐을 지지 구간 전체로 잰다
- 한 번 디딘 동안 실제로 땅에 닿아 있어야 하는 점(평평 = 발끝·뒤꿈치 둘 다, 뒤꿈치 듦 = 발끝, 발끝 듦 = 뒤꿈치)이 그 점이 **처음 닿은 자리**에서 벗어난 최대 거리(최대 이탈)와 움직인 거리(누적, 평평할 때는 두 점의 합)를 구간마다 적습니다. 발끝/뒤꿈치 축 바뀜도 함께 적습니다(`flat>toe` 등).
- 측정이 실제로 잡는지 확인: 걷는 중 디딘 자리를 일부러 5mm 옮기면 최대 이탈 5.00mm로 잡힙니다(`test/stance_measure_sanity.mjs`).
- 결과: 대기·걷기·달리기·웅크려 걷기·걷기→달리기→멈춤·뒤로 돌기·돌아서 걷기의 모든 지지 구간에서 최대 이탈 0.00mm, 한 구간 누적 최대 0.00~0.47mm. 디딘 발은 계산상 세계 좌표에 고정하므로, 이 값은 "다리가 닿지 않아 발이 끌려간 일이 없다"는 확인입니다(측정 방법이 보장하는 범위는 여기까지).
- 처음 이 측정을 넣었을 때 걷기 32mm, 달리기 40mm 이탈이 나왔습니다. 원인은 **출발 첫 걸음**이었습니다: 한쪽 발이 출발 자리부터 너무 오래 디딘 채 남아 다리가 닿지 않았습니다. 출발 위상·첫 걸음 길이·가속(9 → 4m/s²)을 고쳤습니다.

### 3. 걸음과 상체 (짧고 잦은 걸음·굳은 상체 지적)
- 보폭: 디딘 발이 몸에 대해 움직일 수 있는 거리를 걷기 0.66 → 0.80m, 달리기 0.58 → 0.84m로 넓혔습니다. 대신 엉덩이를 걷기 3cm, 달리기 12cm 낮춰 다리를 굽혀 씁니다(달리기는 디딘 동안 더 내려감). 걷는 속도는 1.4m/s(전 1.5).
  - 지금 구현의 값: 걷기 1.4m/s 보폭(두 걸음) 1.33m · 분당 약 126걸음, 달리기 4.2m/s 보폭 2.80m · 분당 약 180걸음(전 판은 약 164·약 261). 사람의 "정답 값"으로 쓰지 않고, 크기·속도·보폭·골반 움직임이 함께 그럴듯한지는 영상과 직접 플레이로 봅니다.
- 상체: 디딘 발 쪽으로 골반이 옮겨 감(걷기 2.8cm), 흔드는 다리 쪽 골반이 내려감(약 3.5°)과 척추가 되돌려 어깨를 거의 수평으로, 골반 비틀림과 가슴의 반대 돌림을 키움, 팔 흔들기 키움(걷기 24°)과 빗장뼈가 함께 움직임. 팔·골반은 다리 위상을 부드럽게 따라가는 값으로 그립니다(다리 위상이 맞춰질 때 한 번에 바뀌지 않게).
- 회전 빠르기 상한: p3d-0.1.0에서 12°에서 15°로 올렸던 것을 **12°로 되돌렸습니다**(지금 최대 11.6°/걸음). 회전량 변화(한 걸음 회전량이 바로 앞 걸음보다 달라진 정도, 물리의 jerk와는 다른 값) 최대는 걷기→달리기→멈춤 9.1°, 급히 뒤로 돌기 9.9°, 점프 5.8°입니다(`results/motion_log.json`에 장면·뼈·시각).
- **사람과의 비교 기준은 아직 없습니다.** 지시서의 "준비된 기본 모션"과 같은 시점·속도로 견줄 자료가 필요합니다. 후보:
  1. Mixamo의 걷기·달리기(제자리) 동작 — 사용자의 Adobe 계정으로 내려받은 FBX
  2. three.js 예제의 X Bot(걷기·달리기 클립 포함, GitHub에서 받을 수 있음. 출처가 Mixamo라 재배포 조건이 불분명 → 저장소에 넣지 않고 비교에만 쓰는 안)
  3. CC0 동작 묶음(Quaternius 등, 이 환경에서는 배포처가 막혀 있어 사용자가 받아 줘야 함)

## W0. 선택한 것과 이유

### 엔진: Three.js 0.187.0 (MIT) + 직접 만든 이동·접촉 제어
- 이 개발 환경에서 **실행·검증·전달을 모두 할 수 있는** 방식입니다. 헤드리스 Chromium에서 WebGL2가 돌아가서(소프트웨어 렌더러 SwiftShader) 자동 시험과 영상 녹화를 여기서 할 수 있습니다. 결과물은 한 파일 HTML이라 설치 없이 열립니다.

- 물리는 `lab/docs/3D_시제품_범위.md`의 **접근 A**(엔진의 충돌 조회 + 직접 만든 등반 제어)로 시작했습니다. 지형은 축에 나란한 상자이고, 디딜 높이 찾기와 옆면 막기를 직접 계산합니다. 접근 B(엔진의 물리 관절, 예: Rapier)와의 비교는 W2의 접촉 장면에서 합니다.
- 2D 소스를 보존하려고 **별도 폴더** `proto3d/`에서 작업합니다. 이 세션은 정해진 브랜치(`claude/trusting-wright-ov2jvz`)에만 올릴 수 있어서, 별도 브랜치는 만들지 않았습니다.

### 임시 사람형 캐릭터: 직접 만든 뼈대 21개 + 스키닝 메시 (`src/rig.js`)
- 출처: 이 저장소에서 코드로 만든 것입니다. 외부 모델·모션 파일을 쓰지 않아 **이용조건 문제가 없습니다**.
- 뼈대: hips → spine → chest → neck → head, chest → shoulder → upperArm → foreArm → hand(좌우), hips → upLeg → leg → foot → toe(좌우).
  - 어깨·척추·골반·팔꿈치·손목·무릎·발목이 움직입니다.
  - 흔한 사람형 뼈대와 같은 계층이라, 나중에 다른 모델이나 모션으로 바꾸기 쉽습니다.
- 몸 치수: 키 약 1.77m, 다리 0.84m(넓적다리 0.43 + 정강이 0.41), 팔 0.57m.
- 겉모양은 상자·원기둥을 이어 붙인 **임시**입니다. 회색 윗옷, 남색 바지, 손목·발목의 작은 좌우 표시(왼쪽 주황, 오른쪽 파랑)를 썼습니다. 최종 캐릭터 미술이 아닙니다.
- 나중에 바꿀 후보: 사용자가 내려받은 Mixamo 캐릭터(Adobe 계정 필요, 이용조건은 Adobe FAQ에서 확인), CC0 캐릭터 묶음(이 환경에서는 일부 배포처가 막혀 있음).

### 기본 모션: 클립 재생이 아니라 "상태 값 + 다리 IK"로 만든다 (`src/motion.js`)
- 대기·걷기·달리기·웅크리기·웅크려 걷기·점프 준비(모으기)·밀기·공중·착지를 하나의 자세 생성기로 만듭니다. 섞는 값(속도, 달리기 정도, 웅크림, 모으기, 공중, 착지 충격)이 시간에 따라 부드럽게 바뀌어서 동작 사이가 이어집니다.
- **이동은 입력과 물리가 정하고, 애니메이션은 몸을 옮기지 않습니다**(`controller.js` = 이동, `motion.js` = 그 자리에 맞는 자세). 애니메이션의 이동량으로 몸을 움직이는 구간은 없습니다.
- 걸음 위상은 **실제로 간 거리 ÷ 보폭**으로만 나아갑니다. 디딘 발은 세계 좌표에 고정하고, 다리가 모자라면 발끝이나 뒤꿈치를 축으로 발목을 들어 축 자리는 그대로 둡니다.
- 무릎은 두 마디 IK로 발끝 쪽을 향합니다. 팔은 걸음에 맞춰 흔듭니다(팔 IK는 W2에서).
- 점프: 모으기(웅크림) → 떼면 **밀기**(발을 디딘 채 0.14~0.24초 다리를 펴며 발끝으로 섬) → 공중 → 착지(내려오던 속도로 무릎을 굽혀 받음).
  - 점프 높이는 사람의 제자리 점프 범위로 두었습니다: 짧게 누르면 약 0.21m, 0.6초 모으면 약 0.47m(몸 자리 기준).
  - 높은 단(0.55m)은 공중에서 다리를 당기는 몫(0.24m)으로 올라섭니다.

## 조작 (지상 이동 문맥, 모두 `src/input.js`의 표에서 읽음)

  - 돌다가 무릎이 옆으로 꺾임(무릎 방향을 발 방향 기준으로 바꿈)

## 알려진 한계 (이번 판)
- **걸음이 사람보다 잦습니다.** 걷기 1.5m/s에서 분당 약 154걸음(사람은 약 110), 달리기 4.2m/s에서 약 232걸음(사람은 약 170)입니다. 디딘 발이 다리로 닿는 범위 안에 있게 보폭을 묶었기 때문입니다. 골반 돌림·엉덩이 내림을 더 넣으면 보폭을 늘릴 수 있습니다.
- 팔은 걸음에 맞춘 흔들기뿐입니다(손 IK·잡기는 W2).
- 시점 카메라가 벽을 통과합니다(충돌 없음). 일부 브라우저는 Alt를 메뉴 키로 쓰므로 막아 두었지만, 브라우저마다 다를 수 있습니다.
- 헤드리스 소프트웨어 렌더러에서 30~60fps가 나옵니다. 실제 그래픽 카드에서는 더 빠를 것으로 봅니다(확인하지 않음).
- **자연스러움과 손맛은 사람이 직접 해 보고 판단해야 합니다.** 위 결과는 모두 자동 측정입니다.
